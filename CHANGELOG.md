## 1.2.43 — 2026-10-20
- `fm task finish` names a step whose last run failed ("its last run failed; record a passing run …", with the command) instead of saying it has no verify command or evidence (T-1272)
- Secrets: one placeholder rule. The commit refusal and the close warning now agree on what a fake value is; for a token (`sk-`, `ghp_`, `AKIA…`) only a whole placeholder word (example, placeholder, changeme, dummy, redacted, your-key) or a run of x's excuses it, so a real key that happens to contain "your" or "fake" is still refused (T-1273)
- `fm code tui [REQUEST]`: Foreman Code in a terminal UI (T-1283). It runs `fm code --json` as a child and draws from its events: the stations as a track, each check as a PASS / RED / FAIL chip, changed files as +/− bars, a time chart per step, tokens per model call, and an activity log where a guard refusal stands out (the model's own words behind `t`). `d` shows the diff, `h` past runs (replayed from `code/<task>.events.jsonl`), `m` picks the model or worker for the next request, `s`/`r` stop and resume, `?` lists the keys. Themes (night, paper, mono), colours, layout and keys come from `$FOREMAN_HOME/tui.toml`, one line per bad setting; `--print-config` prints it. A Python file in `$FOREMAN_HOME/tui/` adds panels, commands and event handlers (`templates/tui/cost_meter.py` is a sample); a project's files are never loaded. `--plain` prints one line per event, `NO_COLOR` is honoured, under 60 columns it shows the log alone, and `--snapshot FILE --events RUN` draws the screen to SVG (the site's picture). fm code's events now carry `ts`, and `changed` carries each file's added and removed lines
- `fm code --worker`: your own uncommitted work survives a worker turn. A file you had changed or added that the turn deletes, stashes or cleans back to HEAD gets your version back and the revert is reported; the worker's own edits to such files stay (T-1270)
- The Pages workflow builds with read-only permissions and deploys in a separate job that alone holds the Pages and OIDC tokens; every action in both workflows is pinned to a commit SHA, and a test keeps them that way (T-1245)
- Foreman's reply format now lives in its rules file (sent once a session), and `fm install-user` no longer selects Foreman's output style, removing it where an older install selected it: Claude Code's per-turn reminder of that style was 2.7% of what entered the context, the largest part of Foreman's own 6.8% (T-1279)
- `fm code --worker --verify`: a worker turn can't change the check that judges it. Edits to the files and folders the verify command names, or a new file in such a folder (a `conftest.py`), are put back and reported, and the task still closes on the real check (T-1271)
