# Brainstorm — lens: bold bets

- **Invert the teacher: let the 0.6–4B student grade the 27B** (and the frontier) on every close, and file a "regret" row whenever the small model's abstain or reject was right. — FEATURE — value 5 — effort M — risk med — category: training loop
  Why: the pack wants "a better decider… how it improves every Rune generation," and the standing rule rewards signals Sampo didn't author. The whole decider is a bet that a small local model can out-judge the big one on *this* project; the only honest evidence is letting the weak model vote and keeping the disagreements. The user's "think:false reaches Ollama" and "6 of 10 died with reasoning eating budget" prove the small arm is fragile and untrusted — grading is the cheapest way to earn trust. Assumption: the 0.6B head can abstain cleanly before it can judge.
  Done when: `samo decide grade` reports, per slot, the share of closes where the small model's verdict ≠ the big model's AND the small model was later vindicated by the user's undo; that share is a first-class exam line.

- **Bet the whole product on one number: "decider beats plain" on whole held-out projects, or Sampo retires the slot.** — FEATURE — value 5 — effort L — risk med — category: capability map
  Why: the pack lists ~200 decider ideas and "Do less: ship the data export, the kNN oracle, and the leave-one-project-out bench; defer all training." The standing rule is a capability whose free arm beats the session arm is a top gap. The bold move is to make the *only* adoption criterion a whole-project leave-out delta, and auto-demote any slot whose margin is within noise. This kills the idea zoo at its root.
  Done when: `samo doctor` prints one line per adopted slot: delta-over-plain, holdout project id, and a "retire if below X" fuse; a slot that misses for two Rune generations is auto-retired with a receipt.

- **The decider is a git object, not a model file.** Weights, embeddings, the training manifest and the leave-out bench all live in `.samo/decider/` and are content-addressed; a "model" is a commit you can `git bisect`, diff and `git revert`. — CLEAN — value 5 — effort M — risk low — category: approaches
  Why: the pack's own pain is rename drift, symlink path misses (T-2967) and "the repo mirror is still named .foreman/." Making the decider a git object solves versioning, provenance, rollback and the "retrain by a content hash" idea in one stroke, and makes the museum/frozen-twin ideas trivial. It also answers the earlier "which model is running?" question with a `git show` instead of a dashboard.
  Done when: `samo decide rollback <commit>` restores the prior decider and the Ward canary passes; a `git diff` between two decider commits shows only weight/manifest deltas.

- **Wild — Train on *regret*, never on labels.** The only training signal is "the user undid it" or "the user re-asked." If a decision survives 14 days un-undone, it's a positive row with no human touch. — FEATURE — value 5 — effort M — risk med — category: unspoken needs
  Why: the user keeps saying "I want it to still get done without burning a fuck ton of money, and quick." Hand-labeling 2,900 briefs is exactly the money-and-time they don't have. Undo and re-ask are *already* in the ledger and are the purest taste signal. This also pre-answers "what does a project with fewer than 20 briefs get" — it gets nothing until it has regret to learn from, and the model abstains until then.
  Done when: the training table is generated purely from undo/re-ask events; a row with neither is unlabelled and the head abstains on its class; a planted "user will undo this" scenario is caught on retrain.

- **Wild — Federate *regret*, not weights.** Each of the user's machines contributes only its regret rows (already de-identified by construction), and the shared base re-trains from the union. No repo text, no briefs, no embeddings leave a machine. — SECURITY — value 5 — effort M — risk med — category: privacy and local-first
  Why: "the user's own machines" appears in their words, and the earlier "federate failure shapes" / "pass lessons by spore" ideas all assume text sharing. Regret rows are tiny, inherently de-identified (an undo carries no file names), and are the *only* thing that can't be replayed from a repo. This makes the cross-machine bet safe by construction.
  Done when: a sync on machine B changes the shared base only via machine A's regret rows; a scan of the union finds no path, name or repo text that was ever on machine A.

- **One decision, one typed sentence, or silence.** Every slot answers in a single constrained-decoding sentence with a confidence, or it outputs `abstain <cause>`. No prose, no JSON, no dashboards. — CLEAN — value 4 — effort S — risk low — category: approaches
  Why: the pack's UI is already dense (panes, lanes, graphs, charts). A decider that floods it with prose is a regression. The grammar gives the Ward, the exam and the UI one thing to parse. It also makes "show which slots use a model" a one-line `samo status` instead of a page.
  Done when: every model call is validated against the grammar with bounded repair; a malformed output is logged as `abstain malformed` and the rules arm takes over; no slot emits free prose.

- **Bet the Ward on the model, but the model may only *tighten*.** The rule-based Ward stays the floor; a risk head can add stricter refusals, never loosen. A removed Ward fails loud (antitoxin). — SECURITY — value 5 — effort M — risk high — category: agents of agents
  Why: the pack's guard work (T-2967, the symlink miss, the over-refusal) shows the Ward is fragile and hand-tuned. A trained head that can only make it stricter is strictly safer and lets the Ward "grow scar tissue" from every near-miss without a human writing a rule. The antitoxin answers "what happens when the model is wrong."
  Done when: a mutation test shows the head can refuse a planted risky command the rules miss; removing the head's output never *permits* a previously-refused command; a near-miss in the ledger auto-appears as a new stricter rule on retrain.

- **Wild — The model writes the next Moonshot, scored wildness 1–5 by the cold reviewer.** The decider's job isn't only to decide; it's to *generate* the next campaign from the regret ledger. — FEATURE — value 4 — effort L — risk med — category: delight
  Why: the standing rule says moonshots must be wild (wildness ≥4). The decider already holds the user's taste (undo/re-ask). Letting it *propose* the next moon — "here's the wild thing you'd want, derived from what you regret" — turns the decider from a cost center into the idea engine. It pre-answers "which slot has the biggest gap" by generating toward it.
  Done when: `samo decide moonshot` emits three candidates with a wildness score from the existing cold reviewer; at least one survives the kill stage in a real funnel run.

- **Cold-start a new project by *regret fingerprint*, zero-shot, in minutes.** A fresh Sampo project with <20 briefs gets the shared base plus the regret rows of its nearest sibling (by stack-card similarity), and abstains everywhere else. — FEATURE — value 4 — effort M — risk low — category: unspoken needs
  Why: "what does a project with fewer than 20 briefs get" is an open question from earlier brainstorms. The honest answer is: almost nothing, until it has its own regret. But a regret fingerprint from a sibling project is a free, de-identified prior that respects the "no model below the line" rule. This is the "seed cold-start priors" idea made concrete and safe.
  Done when: a new project's first `samo decide` call returns a verdict (not abstain) on a task class its sibling has regret history for, and abstains on everything else; the sibling's regret rows are present in the union but no sibling text is.

- **Make "will this close hold?" the first and only trained head, with a veto on close.** Everything else (approach-chooser, loop-predictor, cost-estimator) waits until this one earns its delta. — PERFORMANCE — value 5 — effort S — risk low — category: capability map
  Why: the pack lists six false dones and a "false-done detector" is already an idea. The single most valuable decision is the one that prevents a bad close from shipping under the push grant. Shipping one head first respects "do less" and gives the whole loop a measurable, user-visible win on day one.
  Done when: a close with a planted "this will be reverted in 3 days" pattern is blocked by the head; the head's veto is logged and the user can override with a reason that becomes a negative row.

- **Wild — Run the model as the Ward's attacker in its own exam.** Each Rune generation, the decider tries to *bypass* the Ward; the Ward re-trains its stricter rules from every successful bypass. A standing Red Queen. — SECURITY — value 5 — effort L — risk high — category: agents of agents
  Why: the pack already has "train a Ward classifier, plus an attacker to probe it" and "run a Red Queen arms race." Making the *decider itself* the attacker is the bold, self-contained version: the model that decides what's safe also knows how to evade it, so the Ward is always one step behind a model that's already on-box. It answers "which model decision is made from text a repo wrote" by testing the channel.
  Done when: a nightly `samo decide redteam` finds at least one bypass the current Ward misses; that bypass becomes a planted test the Ward must pass before the next Rune ships.

- **The decider is the *next user*, not a helper.** Every `samo ask` is answered by the decider drafting the user's likely reply, shown as a one-word veto. The user's edits to the draft are the next training row. — FEATURE — value 4 — effort M — risk med — category: unspoken needs
  Why: the user's words keep circling "manage all of that across sessions too… even without direct access." The deepest unspoken need is *not having to be there*. If the decider can answer the routine "yes/no" asks as the user would, the drive unblocks itself and the user's attention goes to the 20% that matters. This is the "Kev-twin" idea, but scoped to one slot and one sentence.
  Done when: on a held-out set of past `fm ask` questions, the decider's draft matches the user's actual reply ≥70% of the time; a mismatch is logged and the user's correction becomes a row; the user can veto a *class* of asks in one command.

- **A "decider obituary" — the model writes its own retirement when a slot stops earning.** Each adopted slot carries a fuse: if its holdout delta is within noise for two consecutive Rune generations, the model writes a one-line reason and the slot auto-demotes to the rules arm. — CLEAN — value 4 — effort S — risk low — category: capability map
  Why: the standing rule is "only proven harm or exact duplication removes an idea, with the reason recorded." The obituary makes removal *self-driven* and *recorded*, which the tower already does for tasks. It also answers "what does a user who never read MASTER.md need to see" — a slot that writes its own "I'm no longer earning my tokens" is more legible than a dashboard.
  Done when: a slot whose holdout delta drops below the floor for two generations is auto-demoted; the obituary line is in the ledger and `samo doctor` prints it; re-adoption requires a new holdout delta above the floor.

- **Wild — Ship Sampo as *one signed file*: the decider is the product's core, not a feature.** The weight manifest, the grammar, the Ward rules and the training lake all compile into a single attested artifact. "Installing Sampo" means running one file. — SECURITY — value 5 — effort L — risk high — category: every device and surface
  Why: the pack's "produce a reproducible, attested plugin release" and "pin and record the serving stack" are stepping stones. The bold bet is that the *discipline layer* is the model, and the model is the artifact. This answers "how it is trained and served on this box" with "it is the box," and makes the per-project adapter, the consent flag and the rollback all properties of one signed object.
  Done when: `samo install <file>` sets up the full decider, Ward and training pipeline from one attested blob; `samo verify` re-checks the attestation at session start; the file's content hash matches the `.samo/decider` git object.
