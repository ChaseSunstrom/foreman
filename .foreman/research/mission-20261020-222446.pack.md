## fm code today (the subject of this brainstorm)

`fm code "<request>"` is Foreman's own harness: the harness, not the model, runs plan → task → checks fail first → steps → checks pass → close with a commit, and the model fills one small checked JSON slot at a time. Runners: any OpenAI-compatible or Anthropic endpoint (local Ollama/LM Studio/llama.cpp/vLLM or cloud keys, `models.json`), or a coding CLI as a worker (`--worker claude|codex|gemini|aider` or a `CMD {prompt}` template) whose every turn is judged by the harness (guard on each changed file, Git config/hooks restored, a commit undone). With no model, `--worker claude` also plans, in Claude's read-only plan mode. A question gets an answer from the files (no task). `fm code tui` is a terminal UI (own ANSI renderer, 24-bit colour, motion: pulse, travelling light, eased counters, flashes, a close wave; panels: track, activity, checks, changed files, time, tokens; keys: n new, h history, m model/worker picker, d diff, t thoughts; themes night/paper/signal/mono; Python extensions add panels/commands). `fm code bench` grades a model or CLI on seeded tasks. Real runs: 7/7 request kinds (fix, feature, rename, docs, question, new project, JavaScript) closed with only the claude CLI.
