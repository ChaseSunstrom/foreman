# Brainstorm — lens: blind spots

- **Stamp what each judge child actually received** — FIX — value 5 — effort S — risk low — category: judge integrity
  Why: assumption: the class is "partial input" (T-2566, where a split was silently ignored). Judge children get capped packs. If an evidence file is truncated, a verdict like "matches the sentence" rests on half the artifact, and nothing records that.
  Done when: every judge verdict stores bytes and files sent versus bytes and files the child echoed back, and a truncated or mismatched receipt makes the proof `unproven: partial-evidence` (a test truncates a screenshot bundle and sees this).

- **Fence hand edits to generated files** — FIX — value 4 — effort M — risk low — category: provenance
  Why: answers the open question "when a human edits a Foreman-generated file by hand, which reader overwrites it?". Baselines, goldens, steers, goals and `coverage.md` are all regenerated by something. Question to ask: which writers can erase a human's correction?
  Done when: each generated file carries a content-hash header, and writers refuse to overwrite a file whose body no longer matches without `--accept-edit`. The accepted edit is logged as a user correction.

- **Lint closed enums against their consumers** — CLEAN — value 4 — effort M — risk low — category: gauge hygiene
  Why: assumption: the class is T-2534/T-2566, where one reader silently ignored an input class. Verdicts, proof kinds, unproven reason codes and bet kinds are closed lists with many readers. Adding a member can leave a reader that quietly drops it.
  Done when: a test adds a dummy member to each enum and fails if any reader's output doesn't change or name it.

- **Map prover reach** — FIX — value 4 — effort M — risk low — category: dark capability
  Why: the Genesis rule says a capability must be called by a real session path. Provers like `fm shot` and `fm flow` are exactly the kind that exist but are only invoked when the user remembers them. Question: which verbs does no hook, skill or `fm next` row call?
  Done when: `fm doctor` lists each prover with its calling session paths, and a prover with none is flagged "dark".

- **Treat a user's re-run of a proof command as distrust** — FEATURE — value 4 — effort M — risk low — category: trust signal
  Why: the user type-checks Foreman by hand (earlier asks about verifying Foreman). When the user runs the same command Foreman said it ran, that is a signal the proof didn't convince, and nothing records it. This is a signal Foreman didn't author.
  Done when: transcript mining counts "user re-ran a command from a proof record within an hour". `fm outcomes` shows it per proof kind and per claim shape.

- **Canary the judge on model changes** — PERFORMANCE — value 4 — effort M — risk med — category: judge drift
  Why: the harness model IDs move (Sonnet 5.5 now). A judge child's verdict on the same evidence can shift silently when the model changes. "Calibrate the cold-read grader" exists, but nothing triggers it on a model change.
  Done when: a stored set of about 20 evidence bundles with human labels is re-judged whenever the judge model ID differs from the last run. An agreement drop of more than 10 points marks that judge's proofs "provisional" in the receipt.

- **Anchor each proof to the user's verbatim sentence** — FEATURE — value 5 — effort M — risk low — category: meaning
  Why: the class is input contamination (T-2554, where Foreman's own briefs were read as the user's asks). For "does it do what the user meant", the claim text in a proof record may be a paraphrase by Foreman or a child, so the proof can pass a different claim.
  Done when: proof records store the verbatim capture id plus the claim text, with a token-overlap score. Below a set threshold the finish says "proved a paraphrase", and a test with a drifted claim shows it.

- **Record who wrote each answer key** — CLEAN — value 4 — effort S — risk low — category: measurement integrity
  Why: the steer says exam scenarios come from a child that never sees Foreman's code, but prover fixtures (red fixtures, bug zoo, goldens) may be Foreman-authored. Question: which headline recalls rest only on keys Foreman wrote?
  Done when: each fixture has an `author: foreman | child | user | outside` field, and the headline prover recall counts only non-Foreman authors. Foreman-authored keys are reported separately.

- **Print the verdict-changing defaults in every proof line** — FEATURE — value 3 — effort S — risk low — category: hidden premises
  Why: assumption: viewport size, timeouts, mask regions, retry counts and noise floors act as unlisted premises. Two proofs of the same claim can disagree only because of a default.
  Done when: a proof line shows any parameter that differs from the stored baseline and any that was defaulted. A test changes a default and sees the line change.

- **Wild: ask a ghost-writer for the most convincing false "verified" report** — FEATURE — value 4 — effort M — risk low — category: adversarial
  Why: wild. A tool-less child sees only the diff and the claim and writes a persuasive but false finish report. The real gate must reject it, and every accepted fake becomes a red fixture. It tests the gate on the writer's side, not the prover's.
  Done when: a nightly run reports the share of fake reports the gate passed, and passed fakes are filed as fixtures.

- **Wild: weekly try to disprove one closed claim by another route** — FEATURE — value 3 — effort M — risk low — category: second method
  Why: wild. The night tick picks one random closed, proven claim and tries the cheapest prover that wasn't used originally. A disagreement reopens the claim with the disagreeing evidence.
  Done when: a ledger of attempts, agreements and reopens exists, with one planted wrong proof that a drill catches.

- **Wild: let proofs go dormant on silence** — FEATURE — value 2 — effort S — risk low — category: trust decay
  Why: wild. A proven label is not shown as current when its covered files and the toolchain haven't been touched for 90 days and no session has re-run it. It is shown as "last seen N days ago". This answers "what was missing a week later" by making age visible.
  Done when: finish and status text carry the age of each proof, with a planted 100-day-old proof shown as stale.
