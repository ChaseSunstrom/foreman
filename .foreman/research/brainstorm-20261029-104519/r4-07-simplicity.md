# Brainstorm — lens: simplicity

I read the lens as "do less, delete, make one thing do the job of many". I skipped what the slate already covers (Lite profile, `fm do`, delete adapters, collapse test launchers, settings pruning).

- **Derive the reference docs from `--help` and retire the docs-impact blocker** — CLEAN — value 4 — effort M — risk med — category: docs
  Why: T-1995, T-1996 and the docs-impact suggestion work exist because a missing or misnamed doc path blocks `fm task done`. Docs generated from the command surface leave nothing to point at.
  Done when: the command reference is regenerated by one command, a test fails if it is stale, and `fm task done` has no docs-impact check for the reference pages.

- **Limit DONE-WHEN to one shell command that exits 0** — CLEAN — value 4 — effort M — risk med — category: intake
  Why: the asks carry DONE-WHEN prose, and T-1994 showed a `-k` that matched nothing passed silently. A single exit-code command removes the grammar, the discrimination question and most lint rules.
  Done when: capturing a DONE-WHEN with more than one command or a non-command sentence is refused with a rewrite hint, and `fm batch` runs it unchanged.

- **Ratchet module size in CI** — CLEAN — value 3 — effort S — risk low — category: complexity
  Why: each recent fix adds a predicate, a suggestion or a special case (`_theirs`, title cutting, `-k` AND rule) and nothing removes any.
  Done when: a checked-in file lists line counts for `plugin/lib/*.py`, and a test fails when one grows unless the same task shrinks another or edits the file.

- **Assert a maximum default output length per command** — CLEAN — value 3 — effort M — risk low — category: output
  Why: T-0828 (compact output) is deferred with no enforcement. A line-count test per command stops output creep without a rollout plan.
  Done when: a test runs each top-level `fm` command on a fixture project and fails if default stdout exceeds 12 lines.

- **Merge the hook entry points into one table-driven dispatcher** — PERFORMANCE — value 3 — effort M — risk med — category: hooks
  Why: the gates include `bench_hooks.py --runs 20`, and T-0832 (a shell prefilter) is parked. One entry reading a rules table gives one startup cost and one place to look. Assumption: several hook scripts each pay interpreter startup.
  Done when: `bench_hooks.py` p95 drops at least 20% and every existing hook test passes unchanged.

- **Move vendored skills out of the repo tree into a pinned, lazily fetched cache** — CLEAN — value 3 — effort L — risk med — category: repo size
  Why: `plugin/skills/` holds 1,248 of 1,877 files. Assumption: most are upstream copies, as the "Source anthropic-skills moved" notices suggest.
  Done when: a fresh clone has fewer than 700 files, the skills still load offline after one `fm skills sync`, and `fm doctor` reports any missing pin.

- **Store each task as one plain markdown file** — CLEAN — value 3 — effort L — risk high — category: state
  Why: ids are cross-referenced in commit subjects (T-2001: T-1998, T-1999, T-2000), and a readable file per task would remove the need for a task-lookup command. Assumption: state is currently spread over several formats.
  Done when: `cat .foreman/tasks/T-NNNN.md` shows title, state, DONE-WHEN and proof, and deleting the other task stores breaks no test.

- **Commit each task as one subject carrying one id** — CLEAN — value 2 — effort S — risk low — category: history
  Why: grouped subjects such as "(T-1987: T-1984, T-1985, T-1986)" need parsing everywhere that reads history.
  Done when: a commit-msg check rejects a subject with more than one id, and `fm ship` writes the child ids into the body.

- **Wild: Rewrite `fmcore` from its tests in a scratch worktree and diff the sizes** — CLEAN — value 4 — effort L — risk med — category: rewrite
  Why: assumption: with 385 test files as the spec, a clean rewrite shows how much of the 110 lib files is accretion. Keep it only if it is at least 30% smaller and green.
  Done when: the scratch core passes the unchanged core test modules, and a report lists lines removed per module.

- **Wild: Publish the guard hook as a single standalone file** — FEATURE — value 3 — effort M — risk low — category: distribution
  Why: the guard is the part users value most in bypass mode, and it is buried in a large plugin. One auditable file gives a safe starting point and a lighter way in. Assumption: the guard has few internal dependencies.
  Done when: one Python file under 400 lines, with no imports from `plugin/lib`, blocks the existing guard fixtures when run alone.

- **Wild: Add an `fm forget` that removes Foreman from a project and proves it's gone** — FEATURE — value 3 — effort M — risk low — category: uninstall
  Why: knowing it can be removed cleanly lowers the cost of adopting it. Assumption: removal today is manual.
  Done when: running it on a fixture project leaves `git status` clean and no hooks, rules or state files remain, checked by a test.

- **Wild: Run a quarterly "one-in, two-out" release** — CLEAN — value 3 — effort S — risk low — category: scope
  Why: the deferred backlog is mostly "Later from T-07xx/T-08xx" items, and T-0866 and T-0867 wait on corpora nobody builds. Each new command needs two proven-unused commands or settings removed in the same release.
  Done when: the release check compares the command lists of two tags and fails unless removals are at least double the additions.
