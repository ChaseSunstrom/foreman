# Brainstorm — lens: exam arms for local models

- **Run a paired replacement arm for each not-yet local model** — FEATURE — value 5 — effort M — risk low — category: exam
  Why: the steer says selfjev-4b, jeff, Jevlike and Von wait on an exam arm against the path they replace. T-2887/T-2894 give the held-out data. Assumption: each item has a named incumbent path (regex, rule, Claude call).
  Done when: `sampo louhi models --replace jeff` prints incumbent vs candidate on the same held-out tasks, with the promote/hold rule printed before the run and the result written to not-yet.md.

- **Climb a scaffold ladder per model** — FEATURE — value 5 — effort M — risk med — category: scaffolding
  Why: the goal is for local models to match frontier results through scaffolding. Assumption: rungs are bare, +card, +numbered menu, +verifier loop, +best-of-N.
  Done when: for each model and scenario kind the scorecard names the lowest rung whose held-out pass rate is within a stated margin of the frontier arm, or "none".

- **Ablate every small-model card** — FEATURE — value 4 — effort M — risk low — category: cards
  Why: T-2909 adds a card store and admit rule, but nothing measures whether a card lifts a given model. Assumption: cards can be toggled per run.
  Done when: each card in cards.jsonl has a with/without delta and an n per model, and cards with negative lift are listed first.

- **Publish a frontier-parity curve** — FEATURE — value 4 — effort S — risk low — category: reporting
  Why: the Models section of the site wants numbers (T-2887). Parity as local+scaffold ÷ frontier on identical scenarios shows progress more directly than pass rate.
  Done when: the site's Models section shows one parity ratio per model with n, and the data file is regenerated by one command.

- **Batch exam arms by resident model** — PERFORMANCE — value 4 — effort S — risk low — category: scheduling
  Why: the pack says a llama-swap switch costs ~3 minutes and can't be detected. Assumption: arms are currently ordered by scenario, not by model.
  Done when: an exam run over three models performs at most two switches, and a killed run resumes without redoing finished cells.

- **Measure whether the model knows it failed** — FEATURE — value 4 — effort M — risk med — category: escalation
  Why: "escalate to frontier only when" is a recurring idea, but nobody has measured whether a local model's self-report or sample disagreement predicts its own failure. Assumption: logprobs or N-sample agreement are available.
  Done when: the scorecard reports escalation precision and recall per model, and a rule is promoted only above a stated threshold.

- **Add a zero-token structure arm** — FEATURE — value 3 — effort S — risk low — category: free-arm
  Why: standing rules favour free arms before session arms, and local models fail first on malformed output. Assumption: repair and parse are deterministic.
  Done when: every candidate is scored on valid-output rate and N-sample agreement without grading, and a model under the floor is skipped with the reason recorded.

- **Run a paraphrase contamination arm** — SECURITY — value 3 — effort M — risk low — category: validity
  Why: the steer says exam scenarios come from a tool-less child, but a local model may have seen similar public tasks. Assumption: a child can paraphrase scenarios keeping the answer key.
  Done when: each held-out scenario has a paraphrase twin, and a model with a score gap above a stated size is flagged.

- **Score cost per verified pass** — FEATURE — value 3 — effort S — risk low — category: economics
  Why: a 27B with thinking on may pass more but cost 10× the wall time. Assumption: the T-2893 reasoning switch exposes the token budget.
  Done when: the scorecard has seconds and tokens per passed scenario, and thinking on/off appears as separate rows.

- **Wild: Run a nightly gladiator league** — FEATURE — value 4 — effort M — risk low — category: league
  Why: wild. Idle local hardware at 04:00 could run every model on rotating sealed scenarios and keep a rating per model and rung. A regression alarm would follow when a model file or quant changes.
  Done when: a nightly run appends ratings and one line is shown in the morning when a rating moves by more than its noise.

- **Wild: Compile frontier wins into cards, then test them** — FEATURE — value 5 — effort L — risk med — category: distillation
  Why: wild. When the frontier passes a scenario that a local model fails, a child writes a card from the trace. The exam then re-runs the local model with the card on a held-out twin, and the card is kept only if it lifts the score.
  Done when: a failing scenario yields a candidate card and a keep/drop verdict with before and after numbers.

- **Wild: Feed a poisoned card to test robustness** — SECURITY — value 3 — effort S — risk low — category: robustness
  Why: wild. A card that is subtly wrong tests whether a small model follows scaffolding blindly. This matters once thousands of cards exist. Assumption: cards are injected as plain text.
  Done when: the exam includes planted-bad cards, and the model's follow rate is reported and a model above a stated rate is gated from card-heavy rungs.

- **Wild: Let a small model author scenarios** — FEATURE — value 3 — effort M — risk med — category: scenarios
  Why: wild. Compare scenarios written by a local model with the tool-less Claude child's on diversity and difficulty, to see whether exam authoring can be free.
  Done when: a report gives the overlap and the difficulty spread of the two scenario sets, with a keep or drop verdict on the local author.
