# Brainstorm — lens: the unprovable (invented): whatever can't be proven is labelled unproven where the user sees it; an unproven claim never counts as done

- **Make "unproven" a first-class task state, not a note** — FEATURE — value 5 — effort M — risk med — category: proof
  Why: T-2273 rolls up unproven tasks, but a done task still counts as done. Assumption: done and unproven are separate counters today.
  Done when: a task closed with only typed or inconclusive evidence shows `done (unproven)` in `fm status`, the pane, and the site, and the plain "done" count excludes it.

- **Give every unproven claim an expiry and a one-command upgrade** — FEATURE — value 4 — effort M — risk low — category: proof
  Why: The rollup lists unproven tasks but gives no path out. Assumption: users let the list grow.
  Done when: each rollup line prints the exact `fm prove` or `fm task evidence` command that would turn it proven, and running it moves the task out of the list.

- **Label model-judged evidence as unproven unless a user-owned check backs it** — FIX — value 5 — effort M — risk med — category: proof
  Why: The earlier question "which verbs have a model on both sides with no user-owned check" and the cold-read rule (T-2246). Assumption: Haiku reads and second reads can currently count as evidence.
  Done when: a criterion whose only evidence is a model verdict reports `unproven: model-judged`, and a test closes one such task and sees it in the rollup.

- **Stamp every number with its witness** — FEATURE — value 4 — effort M — risk low — category: observability
  Why: Earlier question: numbers shown that nobody but the producing code has checked. Stats refreshed daily on the site (T-2326) are one example.
  Done when: each stat on the site and in `fm status` carries a `checked by: <independent source | self>` tag, and `fm doctor` lists self-checked ones.

- **Prove docs against code with executed examples** — FEATURE — value 4 — effort M — risk low — category: docs
  Why: The Seed row names docs-against-code proof kinds; the README and MASTER.md quote commands and flags. Assumption: no check runs them.
  Done when: `fm prove --docs` extracts every fenced `fm ...` command and flag from the docs, runs `--help` or a dry run on each, and fails with the file:line of any that no longer exists.

- **Count unproven UI changes by diff, not by whether the author remembered** — FIX — value 4 — effort S — risk low — category: ui
  Why: The rollup includes "UI changes with no visual check". Assumption: detection depends on the task being tagged UI; a diff touching `templates/web` or `mods/foreman-ui` should force it.
  Done when: a task whose diff touches those paths with no `fm shot` or `fm flow` artifact appears in the rollup even when untagged.

- **Block a goal's "finished" while any contents row is unproven** — FEATURE — value 5 — effort M — risk med — category: goal
  Why: The standing intent is that done must be real; the goal's Stop gate is the place it bites. Assumption: it currently counts tasks, not evidence quality.
  Done when: Stop on a goal with an unproven row prints "finished except N unproven" and offers prove, accept-as-unproven (user-only), or park.

- **Add a user-only "accept as unproven" verb that records a reason** — FEATURE — value 3 — effort S — risk low — category: consent
  Why: Like `fm mandate set`, which is the user's to run (T-2252). Unproven items need an exit the model can't take itself.
  Done when: `fm accept-unproven ID --why` works only from the user channel, the guard refuses it from a session, and the rollup shows it as "accepted by user".

- **Flag proof that could not have failed** — FEATURE — value 5 — effort M — risk med — category: proof
  Why: Standing rule on metric-gaming; `fm task prove` already shows a test failing without the change. Assumption: not every kind (bench, migration, docs) has an equivalent.
  Done when: each proof kind records a "negative control" run, and a proof with none is labelled `unproven: no control`.

- **Wild: Run a mutation pass on the claims** — FEATURE — value 4 — effort L — risk med — category: proof

  Done when: a seeded one-line break to a task's source makes at least one recorded check fail, or the task is flagged.

- **Wild: Publish an "unproven ledger" page beside the exam scores** — FEATURE — value 3 — effort M — risk low — category: site

- **Wild: Let an unproven claim decay to a bet with a visible age** — FEATURE — value 3 — effort M — risk low — category: delight
  Why: wild. Unproven tasks quietly age; assumption: nobody revisits them. A badge turns amber then red with age, and a nightly job tries to prove the oldest.
  Done when: the oldest unproven task is attempted automatically each night and either leaves the list or records why it can't.

  Done when: `fm prove --infra` records a plan or dry-run output for a config/CI/install change, and a task with none is labelled `unproven: infra`.
