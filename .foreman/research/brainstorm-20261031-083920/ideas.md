## Kill it fast (the quickest test that would show it isn't worth building)
- Mutate the claim, not the code — Mutate 20 past claims by hand; if the existing checks already flag over 90% as false, there's no gap to fill.
- Docs-vs-code claim extractor — Run a regex extractor over the README and docs; if under half the extracted claims are checkable, it's noise.
- Perf claim needs a recorded measurement or a label — Grep the last 30 perf claims; if nearly all already cite a measurement, the gate is redundant.
- Screenshot must be looked at, by something else — Feed 10 known-broken screenshots to a second model; if it misses more than 3, the look-check isn't evidence.
- Citation gate for research tasks — Audit 10 past research outputs; if uncited claims are under 10%, skip the gate.
- Infra dry-run diff as evidence — Run `plan` on 5 past infra tasks; if the diffs are unreadable or empty, they prove nothing.
- Verdict disagreement ledger — Count past judge/writer disagreements; if fewer than 5, a ledger is empty furniture.
- Proof receipt with a "what this does not prove" line — Write the "does not prove" line for 10 receipts; if it's boilerplate each time, kill it.
- Intent-match check: restate the diff back to the ask — Restate 10 diffs against their asks by hand; if all 10 match trivially, the check adds nothing.
- Stale proof expiry — Check how many past proofs went stale and wrong; if zero, expiry is solving nothing.
- Wild: Saboteur lane — Plant 5 bugs in a finished task; if existing proofs catch all 5, no saboteur lane is needed.
- Wild: Claim-to-check compiler for the README — Compile 10 README claims to checks; if over 3 can't be expressed as commands, the compiler is a toy.
- Wild: Proof heatmap on the site — Ask 3 users to read a mock heatmap; if none changes a decision, don't build it.
- Wild: Unprovable-claims court — List 20 claims; if fewer than 3 are truly unprovable, there's no court to hold.
- Make every proof kind emit one signed "proof receipt" record — Hand-sign 10 receipts; if nobody ever verifies a signature, it's decoration.
- Add a docs-against-code proof kind — Diff docs against code on one module; if it finds no real drift, skip it.
- Add an infra proof kind: plan, apply to a scratch target, re-plan to empty — Apply a scratch plan once; if setup takes longer than the task itself, it's too costly.
- Prove "does it do what the user meant" by replaying the ask as an acceptance script — Turn 5 asks into acceptance scripts; if the user rewrites most, the replay misses intent.
- Run a mutation check on each task's new test — Run a mutation tool on 10 new tests; if survivors are under 10%, tests are already strong.
- Close the writer/judge gap with a user-owned checker file — Ask the user to write 3 checker files; if they won't, the gap stays open.
- Re-verify old "done" claims on a schedule (proof decay) — Re-run 20 old "done" proofs; if over 95% still pass, scheduling is waste.
- Add a research proof kind: every claim carries a source and a re-fetch check — Sample 10 research claims for re-fetch; if sources are mostly paywalled or dynamic, re-fetch fails.
- Prove releases by installing the built artifact in a clean venv — Install the last release in a clean venv; if it already passes in CI, it's duplicate.
- Replay the UI proof deterministically with a stored flow and pixel-diff budget — Replay one UI flow 5 times; if pixel diffs flake above budget, it's unusable.
- Wild: Let a proof run a "counterfactual twin" of the repo — Spin up one twin repo; if it takes over 10 minutes, it's too slow to matter.
- Wild: Publish a live "proof ledger" page on the Genesis site — Check whether anyone visits the ledger page; if traffic is zero, don't publish it.
- Wild: A "chaos proof" lane that tries to break each green claim — Run one manual break attempt per green claim; if none breaks, a lane adds only cost.
- Wild: Pre-register the proof before the work begins — Pre-register 5 proofs; if the plan changes mid-task every time, the registration is fiction.
- Score every proof kind by catch rate against later reopens — Compute reopen overlap on 30 tasks; if reopens are under 3, the catch rate is noise.
- Mutation-test each proof kind with planted faults — Plant faults in one proof kind; if it catches them all, you learned nothing about the others.
- Retire a proof kind to advisory after N consecutive no-signal runs, reversibly — Look at the last 50 runs per kind; if none has gone silent, there's nothing to retire.
- Never auto-retire without a user-owned tripwire — Ask who owns a tripwire; if no one, the rule can't ship.
- Run shadow mode before retirement — Count shadow runs available; if too few to compare, shadow mode can't conclude.
- Report theatre cost in seconds and tokens — Log seconds and tokens for one week; if the cost is under 2% of the budget, skip the report.
- Track which criteria were typed evidence and later wrong — Grep reopen notes for typed-evidence criteria; if none were wrong, don't track.
- Escalate a kind that is missing catches — Check if any kind has missed a catch in 30 tasks; if none, escalation never fires.
- Version every proof-policy change in a diffable file — Look at git log for policy changes; if there are under 3, versioning is overhead.
- Wild: Hire a saboteur lane that breaks the code and sees which proofs notice — Same experiment as 11; if the existing proofs catch every planted bug, kill it.
- Wild: Replay old closed tasks with the proof removed — Remove the proof from 5 old tasks; if the outcomes are identical, the proof was cosmetic and this is just an audit.
- Wild: Give each proof kind a visible "trust" badge on the receipt — Show badges to 3 users; if nobody can say what "trust" means, drop it.
- Cold-read the policy file for metric-gaming — Have a second model attack the policy file for gaming; if it finds nothing, move on.
- Compile each user ask into a "meant-it" check the user can read — Compile 5 asks into checks; if the user can't read them in 30 seconds, kill.
- Run the user's sentence through a blind re-implementer — Give 3 sentences to a blind re-implementer; if the results match the originals, the check is redundant.
- Flag tests that pass on the pre-change tree for a different reason — Run 20 tests on the pre-change tree; if under 2 pass, the flagger is almost never used.
- Quote the ask's nouns in the diff evidence — Check 10 diffs for the ask's nouns; if present only by luck or absent in valid diffs, it's a weak signal.
- Make "unproven" show the reason in the user's words — Write 5 "unproven" reasons in the user's words; if they read as generic, drop it.
- Replay the ask against a mutation of the fix — Mutate 5 fixes and replay the ask; if the replay still passes, the check is blind.
- Let the user write the acceptance line first, with a sample — Ask the user to write one acceptance line first; if they skip it, the flow stalls.
- Verify docs claims against the shipped command by running them — Run the documented commands once; if they already run in CI, it's duplicate.
- Score the builder's "done" against the user's later corrections — Count later user corrections on 30 "done" tasks; if rare, the score has no signal.
- Wild: Hire an adversarial user-twin that tries to prove the task didn't do what you meant — Run an adversarial twin on 5 tasks; if it only produces nitpicks, kill.
- Wild: Make the user's exact words the commit message trailer and the site changelog line — Check whether users read commit trailers; if no, it's invisible.
- Wild: Play back the behaviour as a one-screen before/after the skeptic can rerun — Build one before/after; if it can't run under 10 seconds, no skeptic will rerun it.
- Detect asks whose acceptance can't be machine-checked and say so up front — Classify 20 asks; if over 90% are machine-checkable, the warning rarely fires.
- Make "unproven" a first-class task state, not a note — Check whether "unproven" already exists as a note anyone queries; if no one queries, it's a label only.
- Give every unproven claim an expiry and a one-command upgrade — Add expiry to 5 unproven claims; if nobody runs the upgrade command, it's decoration.
- Label model-judged evidence as unproven unless a user-owned check backs it — Count model-judged evidence with no user check; if it's under 5%, skip.
- Stamp every number with its witness — Audit 20 numbers; if nearly all already have a visible source, witnesses add little.
- Prove docs against code with executed examples — Execute doc examples once; if most are non-runnable fragments, it won't scale.
- Count unproven UI changes by diff, not by whether the author remembered — Diff-scan 20 past tasks for UI changes; if the author's own flags already match, it's redundant.
