1. **Answer** — Two causes are grounded in code. The first is the 32 evidence nudges: automatic evidence is tagged `(ac N)`, but the Stop gate looks for `(step N)`. The second is the 6 `plugin` blocks: a bare backtick counts as an "exec API", so markdown backticks in a heredoc are enough to trigger the block. The `rm "$D"` blocks and the repeated failed Bash calls share one probable cause, but I only partly grounded it. I could not read the 32 failed calls' stderr, so that link is inferred.

2. **Findings** (most valuable first)

**F1. Evidence nudge ignores automatic evidence (FIX, S)**
- Friction: "32× the Stop hook held a turn for missing evidence".
- Cause:
  - `_auto_evidence` records a criterion's verify command as `ac=n` only (`plugin/lib/fmhooks.py:1007`).
  - `_evidence_gate` asks `act.has_evidence(step=cur.n)` when a step is current (`fmhooks.py:1172`).
  - `has_evidence` matches the tag exactly, `("step", N)` or `("ac", N)` (`plugin/lib/fmcore.py:791-800`; `_EV_RE` at `fmcore.py:588`).
  - So a step verified by its exact AC command still looks unverified when Claude says "done".
- Change: in `_evidence_gate`, treat any evidence line as sufficient when the step has no evidence of its own but some AC evidence exists. Better, map the step to its ACs. The simplest version is `has_evidence(step=n) or has_evidence()`. Add a regression test.
- Done when: a test records an auto-evidence `(ac 1)` line, then a Stop with "step 1 done" returns no nudge.
- Confidence: high on the mismatch. Medium that it explains most of the 32, because I did not read the events.

**F2. Backtick counts as an exec API in the `plugin` check (FIX, S)**
- Friction: "6× plugin: interpreter code running claude's plugin…".
- Cause:
  - `_EXEC_API` ends with a bare `` ` `` alternative (`plugin/lib/fmguard.py:420-421`).
  - `_CLAUDE_IN_CODE` matches a quoted `"claude plugin …"` (`fmguard.py:418-419`).
  - `_interpreter_writes` blocks when both match, over the whole heredoc body (`fmguard.py:486-488`).
  - Python or markdown text with a quoted `claude plugin test` next to a backtick satisfies both, even though nothing is executed.
- Change: drop the bare `` ` `` from `_EXEC_API`. If JS template literals matter, require `` ` `` only for `node`/`bun`/`deno`, or require it to follow `exec`/`sh`. Add a test with a heredoc that mentions the command inside backticks.
- Done when: that heredoc passes, and `subprocess.run(["claude","plugin","install"])` is still blocked.
- Confidence: high on cause. Medium that the 6 blocks were all this shape, since I did not see the commands.

**F3. `rm -rf "$D"` is blocked even when `$D` was just set to a scratch path (FEATURE, M)**
- Friction: "3× rm-outside … $D" and "2× … $S/vsrc". It plausibly also causes the repeated failed Bash calls that start with `S=/tmp/…`, `F=`, `D=`.
- Cause:
  - `_unresolvable` returns true for any token containing `$` or a backtick (`plugin/lib/fmguard.py:121-122`).
  - `_rm_target_violation` rejects such tokens immediately (`fmguard.py:693-695`).
  - Env assignments are only stripped (`fmguard.py:349`) and never recorded. I found no variable tracking.
- Change: record leading `VAR=literal` assignments earlier in the same command text, substitute them before the check, and let the existing scratch and project rules judge the result.
- Done when: `D=/tmp/x/s; rm -rf "$D/vsrc"` is allowed, while `D=$HOME; rm -rf $D` and an unset `$D` are still refused.
- Confidence: medium. The mechanism is clear, but the cause of the 32 failures is inferred.

**F4. Drive-wait events are logged on every Stop (CLEAN, S)**
- Friction: "32× the drive ended a turn to wait on background work".
- Cause: `_drive` emits a `drive_wait` event on every Stop while anything is running (`plugin/lib/fmhooks.py:1256-1259`). The digest counts events, so one long wait looks like many.
- Change: emit the event only when `d["waiting_on"]` changes, or count distinct sessions in the digest.
- Done when: three Stops during one background task produce one `drive_wait`.
- Confidence: high on the mechanism. Low on whether any of the 32 was a real stall, because I did not inspect events.
