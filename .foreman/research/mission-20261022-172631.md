Never used: capture, design-extract, directions, doctor, improve, intake, library, next, playbooks, reflect, resume, status, tidy. 65 of 82 playbooks never read; the read ones were review/security 14, ui/scene-3d 7, review/code-reviewer 5, ui/motion 4.
- Why, as far as we can see:
  1. The UserPromptSubmit and Stop hooks inject the exact next fm command each turn ("Next: …"), so Claude runs fm directly and never loads the skill that describes the same step.
  2. Most skill descriptions trigger on user words ("status", "where were we") that long autonomous runs never contain.
  3. Claude Code's skill listing budget: Foreman keeps all skill descriptions under 2,000 characters (1,957 used; decision T-1508 kept the cap), which caps the count and makes descriptions terse.
  4. Playbooks hide behind one skill.
- Claude Code facts: a skill is a SKILL.md folder with name and description frontmatter. The model sees only name and description until it invokes the Skill tool. disable-model-invocation makes a skill user-only (/name). Skills can bundle scripts and references loaded on demand. Plugin skills are namespaced (foreman:name). The anthropics/skills repo shows the pattern: one skill per job, and a description that says WHEN to use it in task terms ("Use whenever you are about to …"), with references and scripts beside SKILL.md.
- Constraints:
  - Every feature must work in the Claude Code plugin (skills, commands, hooks, foreman-ui), not only fm code.
  - The guard is never weakened; third-party skills run nothing unguarded.
  - Hook context over ~10 KB becomes a preview.
  - The rules file stays within 80 lines and 6,400 chars.
  - Playbooks are held to the token ratchet.
