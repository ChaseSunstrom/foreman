# Brainstorm — lens: adoption and onboarding

- **Ship Foreman as a marketplace plugin with a zero-wiring default** — FEATURE — value 5 — effort L — risk med — category: install
  Why: Section B: every popular rival installs via `/plugin install` or one npx/uv command and adds commands without rewriting `~/.claude`; Foreman's installer sets bypassPermissions, an output style, autocompact and 20 deny rules (A2). Split into a plugin-only core (hooks, skills, `fm` on PATH inside sessions) and an opt-in `fm setup` that applies the wiring, each change listed with a yes/no.
  Done when: in a clean HOME, `/plugin install foreman@<marketplace>` yields a working `fm status` and the diff of `~/.claude/settings.json` is empty until `fm setup` is accepted.

- **Make bypass mode an explicit, explained opt-in** — SECURITY — value 5 — effort S — risk low — category: trust
  Why: A2: the install only says "Claude Code asks you to confirm once"; bypass is a large trust ask. Default to the user's current mode; `fm setup --bypass` prints what the guard blocks and what it can't, then asks.
  Done when: a fresh default install leaves `permissions.defaultMode` unchanged, and the bypass prompt text names the guard's deny classes.

- **Put `fm` on the shell PATH at install** — FIX — value 5 — effort S — risk low — category: install
  Why: A3: README says "run fm …" everywhere but in a normal shell it's "command not found".
  Done when: after install in a clean HOME, a new login shell runs `fm help` with exit 0; uninstall removes the shim.

- **Add `fm hello`, a 60-second guided first task on a throwaway repo** — FEATURE — value 5 — effort M — risk low — category: onboarding
  Why: A1, A5, A6, A9: README is abstract, `fm init` prints a random slug, `fm task new` and `finish` are discoverable only by luck. `fm hello` makes a temp repo with a seeded bug, walks capture → task → fix → `fm task finish`, and shows the evidence record, with no model calls required (scripted).
  Done when: `fm hello` in a clean HOME completes in under 90 seconds and ends with a finished task visible in `fm status`.

- **Rewrite the README's first screen as a before/after demo** — FIX — value 4 — effort S — risk low — category: docs
  Why: A1: no demo today; rivals lead with a concrete flow. Show one terse request, the recorded evidence, and what a resumed-after-compact session looks like, in under 25 lines, with a bench number once one exists.
  Done when: the README's first 30 lines contain a runnable example whose output is generated by a test that fails if it drifts.

- **Make `fm --help` the 8-verb front door** — FIX — value 4 — effort S — risk low — category: cli design
  Why: A4: `--help` is 231 lines with ticket numbers while the better `fm help` goes unpointed-to. Make `--help` print the core verbs, one example each, and "fm help --all" for the rest.
  Done when: `fm --help | wc -l` is under 30 and contains no `T-` ids.

- **Start `fm doctor` as a first-run checklist, not a failure** — FIX — value 4 — effort S — risk low — category: onboarding
  Why: A8: a fresh install fails its own doctor (missing backup) and prints 40 passes. Show only what needs attention, treat first-run absences as "not yet", and offer the fix command.
  Done when: `fm doctor` on a fresh install exits 0 and prints at most 5 lines.

- **Detect the test runner at `fm check` and offer it as the gate** — FEATURE — value 4 — effort S — risk low — category: onboarding
  Why: A7: with no gates configured nothing is detected; C: the repeated commands are pytest/unittest. Detect pytest/unittest/npm test/cargo test from the project map and offer one yes to save it (never single modules, per C's bad-advice finding).
  Done when: in a fixture repo with `tests/test_x.py`, `fm check` proposes `python3 -m unittest` or `pytest` and saves it on yes.

- **Teach every error and empty state the next command** — FIX — value 4 — effort M — risk low — category: ux
  Why: A5, A6, A9: empty `fm status` shows "Drive: on" unexplained; `task new --help` lists no types or example; `task done` refuses with four bullets and hides `finish`. Add valid values, an example, and a single "do this" line to each.
  Done when: `fm task new --help` lists types and tiers with an example, and a refused `task done` ends with the exact `fm task finish` command.

- **Replace jargon with a 10-word plain glossary surfaced in context** — CLEAN — value 3 — effort M — risk low — category: vocabulary
  Why: A11: brief, evidence, audits, scope, drive, lane, focus confuse newcomers. `fm help terms` plus plain aliases in newcomer-facing text; a lint over README and help output.
  Done when: a test fails if an undefined glossary term appears in README or `fm help` output.

- **Add `fm try`: Foreman for one session that leaves no trace** — FEATURE — value 4 — effort M — risk med — category: trust
  Why: A2, A10 plus B (rivals add commands without rewriting config). Runs Claude with Foreman via `--plugin-dir` and a temp state dir, nothing written to `~/.claude`.
  Done when: after `fm try` exits, a diff of `~/.claude` before and after is empty.

- **Wild: Stranger test in CI** — FEATURE — value 4 — effort M — risk low — category: onboarding
  Why: wild. A cold child with only the README tries to complete a toy task on every release; where it stalls becomes a ticket. Directly measures A1–A11 regressions.
  Done when: CI fails if the stranger child cannot finish the toy task within N turns, and attaches its stall points.

- **Wild: Uninstall that leaves byte-identical `~/.claude`** — FIX — value 3 — effort M — risk low — category: install
  Why: wild-ish, A10: residue after uninstall and "defaultMode = None". Install records a manifest of every change; uninstall replays it in reverse.
  Done when: a round-trip install then uninstall in a clean HOME produces a tree identical to the original.

- **Wild: "Foreman Lite" first week** — FEATURE — value 4 — effort M — risk med — category: adoption
  Why: wild. New projects start observe-only with three visible behaviours (guard, resume, evidence-at-done); `fm more` unlocks features as the user's own usage shows they would help, shrinking the 108-verb surface for newcomers without deleting anything (D).
  Done when: a new project's `fm help` shows at most 8 verbs, and `fm more` reveals the next tier with a one-line reason.

- **Wild: Proof page for newcomers** — FEATURE — value 3 — effort M — risk low — category: trust
  Why: wild; C: only 1 bench case and no published evidence. Generate a static page from the user's own first five tasks showing evidence captured, dangerous commands blocked, and one-step resume, so adoption is justified by their own data.
  Done when: `fm page --welcome` after five finished tasks writes a self-contained HTML with those three counts, none requiring network.
