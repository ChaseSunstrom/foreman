# Brainstorm — lens: delight

- **Make `fm` work in a normal shell** — FIX — value 5 — effort S — risk low — category: first run
  Why: Section A.3. `fm` is only on PATH inside Claude sessions, so a newcomer following the README gets "command not found".
  Done when: in a fresh `bash -lc 'fm --version'` after install, with no Claude session, prints the version, and uninstall removes the shim.

- **Ship a zero-wiring marketplace install and make every `~/.claude` change a step of `fm wire`** — FEATURE — value 5 — effort L — risk med — category: install
  Why: Section B. Every popular rival is one marketplace or npx command that adds commands without rewriting `~/.claude`. Foreman's installer sets bypass mode and 20 deny rules. Assumption: hooks and skills can load from a plain plugin install.
  Done when: `/plugin install` on a clean HOME gives working hooks and skills with `~/.claude/settings.json` untouched. `fm wire` then offers bypass mode, the statusline and the deny rules one at a time, each with a one-line reason.

- **Print an install receipt with per-item opt-out** — FEATURE — value 4 — effort M — risk low — category: trust
  Why: Section A.2. The install output only says "Claude Code asks you to confirm once", and bypass mode is a large trust ask.
  Done when: the installer ends on a numbered list of every setting and plugin it changed, each with its off-switch flag. `--yes` skips the list and `fm unwire N` reverts item N.

- **Generate the README's first screen from a real recorded run** — FEATURE — value 4 — effort S — risk low — category: docs
  Why: Section A.1. The first screen is abstract, and there is no before/after.
  Done when: the README top shows a real transcript of `FIX: login times out` on a fixture repo, regenerated by one script. A test fails when the block is stale against current output.

- **Add `fm demo`: a no-model replay of a seeded-bug fix** — FEATURE — value 4 — effort M — risk low — category: onboarding
  Why: Section A.5 to A.9. A newcomer's first minutes are confusing (a bare slug from `fm init`, a duplicate task, four refusal bullets at `done`). Assumption: a recorded real session can be replayed deterministically.
  Done when: `fm demo` plays capture, plan, red-to-green evidence and `task finish` in a temp repo in under 60 seconds with zero API calls. Each frame names the real command being shown, and nothing outside the temp dir changes.

- **Fade out training wheels over the first three tasks** — FEATURE — value 4 — effort M — risk low — category: onboarding
  Why: Section A.11. Jargon (brief, evidence, scope, drive, lane) is unexplained. Assumption: a counter in state can drive the fade.
  Done when: on tasks 1 to 3, each gate or ceremony step that fires gets a one-line "why" in plain words. From task 4 these notes are gone, and `fm coach on` brings them back.

- **Make a fresh install pass its own `fm doctor` and read like a greeting** — FIX — value 3 — effort S — risk low — category: first run
  Why: Section A.8. A fresh install fails doctor on a missing backup and prints 40 lines of passes.
  Done when: `fm doctor` on a just-installed clean HOME exits 0 and prints at most 5 lines, with "not yet" items marked as such. `fm doctor -v` shows the full list.

- **End every `--help` with a worked example and the valid values** — FIX — value 3 — effort S — risk low — category: cli
  Why: Section A.4 and A.6. `fm task new --help` lists no valid `--type` or `--tier` values and gives no example, while `fm --help` is 231 lines.
  Done when: a test fails for any verb whose help lacks an "Example:" line and its enum values. `fm --help` fits one screen.

- **Fold child tasks into their parent in `fm digest`** — FIX — value 3 — effort S — risk low — category: honesty
  Why: Section C. Of the 370 tasks done in the last week, 159 show as "ungraded" because they were folded into other tasks, which makes the digest look weaker than it is.
  Done when: `fm digest` counts a folded task once under its parent, and its ungraded count drops by those folded tasks.

- **Stop `fm repeats` suggesting single test modules as gates** — FIX — value 3 — effort S — risk low — category: gates
  Why: Section C calls this "bad advice". It surfaces `unittest` runs of one module as every-task gates.
  Done when: given a history of single-module runs plus one full-suite command, `fm repeats` proposes only the suite-level command. A unit test covers that.

- **Wild: Give a first-scan gift at install** — FEATURE — value 4 — effort M — risk low — category: wow
  Why: wild. Assumption: a 60-second read-only scan of the current repo (TODOs, a failing test, a tracked `.env`) is cheap and stdlib-only. It uses the newcomer's own data and no model calls.
  Done when: the installer or first `fm init` prints "I found 3 things I'd queue", each with a one-line `fm capture` to accept. Nothing is written without a yes.

- **Wild: Add `fm learn`, a rustlings-style tutorial** — FEATURE — value 4 — effort M — risk low — category: onboarding
  Why: wild. Six tiny exercises in a scratch repo, each checked by a real Foreman gate (capture, plan, red-to-green, finish, resume after compact, a guard block), so the newcomer learns by seeing each gate pass or refuse.
  Done when: `fm learn` runs the exercises in order and marks each green only when its gate passes. Finishing all six prints a one-line summary and a cheat sheet.

- **Wild: Hold an uninstall exit interview that leaves nothing behind** — FEATURE — value 2 — effort S — risk low — category: trust
  Why: wild. Section A.10. Uninstall leaves empty dirs and a stray `projects/` and prints "defaultMode = None". Assumption: a leaver will answer one optional question.
  Done when: uninstall leaves no residue (verified by a before/after home-tree diff test) and prints a plain "restored your permission mode to X". It asks one skippable "what got in your way?" and saves a pasteable note locally, sending nothing.
