Foreman Code

Foreman Code: the loop, on any model

In progress. fm code is Foreman's own harness: it runs plan, edit, verify and close itself, and the model only fills one small checked slot at a time. That is what lets a small local model do real work, and a big one go faster.

Open the app

fm code on its own opens the app, the way claude does. Inside a project it shows that project's active task, queue, inbox, blocked tasks and past runs; Esc lists every Foreman project on the machine with what each is doing. Enter on a task runs it in its own folder (fm code --task ID: the task's criteria and steps are the plan), n starts a new request there and m picks the runner.

Watch it work

fm code tui runs a request in a terminal UI drawn from the harness's own events: the stations as a track, each check as a pass or fail chip, changed files as bars, where the time went, and tokens per model call. A guard refusal stands out in the activity log; the model's own words are one key away (t). d shows the diff, h past runs, m picks the model or worker for the next request. It moves: the working station pulses, counters and bars ease to their values, a refusal flashes (motion = reduced or off stills it). Themes (night, paper, signal for colour-blind eyes, mono), layout and keys come from tui.toml, and a Python file in Foreman's home folder can add a panel, a command or an event handler.

Examples: real runs of every kind

Each card below is one real run, in a throwaway repo on this machine, with nothing set up but Claude Code's own CLI: --worker claude plans in Claude's read-only mode, then does each step, while fm code makes the task, runs every check before and after the work, and closes it with a commit only when the checks pass. A fix, a feature, a rename across files, docs, a question, a project from an empty folder and another language: the cards are drawn from each run's own events, kept in demo/examples/, and fm code tui --events replays any of them.

Ask about the code

fm code 'what does parse_dates in report.py do with a date that has no timezone?' --worker claude

Plan a question: answered from the files, no task, nothing changed

Answer

In report.py, parse_dates (lines 4-11) parses each row's r['when'] with datetime.fromisoformat (line 7). If the result has no tzinfo (line 8), it treats the value as UTC by calling d.replace(tzinfo=timezone.utc) (line 9). That attaches UTC without shifting the clock time. Every value, naive or aware, is then converted with astimezone(timezone.utc) (line 10) and appended to the returned list, so all outputs are UTC-aware datetimes.

Any model, any CLI

  • Any OpenAI-compatible endpoint: Ollama, LM Studio, llama.cpp, vLLM, OpenRouter, Groq, OpenAI, Gemini's compatible endpoint, and Anthropic's API.
  • Other CLIs as workers. claude, codex, gemini or aider do a step; the harness judges the diff and runs the checks itself.
  • The same guard on every command and edit, through the hook other harnesses use.
  • A bench: fm code bench grades any model or CLI as a Foreman worker on five seeded tasks in throwaway repos, counting a task only when its own check passes afterwards.
