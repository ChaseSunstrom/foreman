What this shows (terminal-ui playbook)

  • Hierarchy and roles: one primary fact per row, seven colour roles, and a glyph for every status (✓ ✗ ▸ ○), so 8-colour and NO_COLOR keep the meaning.
  • Colour depth: the bar is a gradient only in 24-bit; flat in 8 colours; plain glyphs █ and ░ with NO_COLOR.
  • Columns, not characters: the task name carries CJK text and a stray escape code; widths are measured in columns, the cut ends in … and the control byte is shown as ·.
  • Resize and small: every frame is laid out from state at the current width; under 56 columns a one-column form, under 28 a "too small" line naming the size needed.
  • Motion budget: the spinner runs at 10 fps only while work runs, a frame is written only when the picture changed, and reduced motion stops it.
  • Quiet by default: passed checks fold to one line, a failure keeps the command it ran and ends with Next:; lists cap with "+N more".
  • Keys: every action has a key, listed on the last row of the screen; the keys work only while the screen or a control has focus, so typing elsewhere is never caught.
