# Ops playbooks

Running software that people depend on: what to do when it breaks, and what to record so you can tell. Paths are
relative to the playbooks skill.

- `references/ops/incident.md` — Users are hurt now: declare, name roles, triage by impact, mitigate before the cause, a UTC timeline, owned follow-ups.
- `references/ops/observability.md` — Logs, metrics and traces worth having: a question per signal, RED and USE, structured events, a tested JSON logger, a fire drill.
