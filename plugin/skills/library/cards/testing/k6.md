k6 runs JavaScript load scripts with scenarios, checks and thresholds that fail the run when SLOs break.

## Verify
- `k6 run --vus 1 --iterations 1 script.js`: one-iteration smoke run proves the script and endpoints work.
- `k6 run script.js`: full run; exit code is non-zero when a threshold fails.
- `k6 inspect script.js`: the options and scenarios parse as intended.
- `k6 run --summary-export=summary.json script.js`: machine-readable results for CI.

## Test first
Write thresholds first; the run fails until the service meets them.
```js
import http from "k6/http";
import { check, sleep } from "k6";

export const options = {
  thresholds: { http_req_failed: ["rate<0.01"], http_req_duration: ["p(95)<300"] },
  vus: 10, duration: "30s",
};
export default function () {
  const r = http.get(`${__ENV.BASE_URL}/health`);
  check(r, { "status 200": (res) => res.status === 200 });
  sleep(1);
}
```
Scripts live in `k6/` or `loadtests/`.

## Do
- Smoke (1 VU), then load, then stress or spike; keep each as a named scenario.
- Define thresholds on `http_req_failed`, `http_req_duration` percentiles and per-endpoint tags, with `abortOnFail` for runaway tests.
- Prefer open-model executors (`constant-arrival-rate`, `ramping-arrival-rate`) to hold a request rate; closed `vus` models slow down when the server does.
- Use `check()` for response validity and `group` or tags to separate endpoints.
- Read secrets and base URLs from `__ENV` and pass them with `-e`.
- Load test data with `SharedArray` in `open()` at init, not per iteration.
- Run against a production-like environment, never a shared prod.

## Avoid
- No thresholds: the run always exits 0 and CI learns nothing. Add thresholds.
- `check()` assuming it fails the run: it only records a rate. Pair with a `checks` threshold.
- Calling `open()` or heavy setup inside the default function: it only works in init context. Move it up.
- Generators on the same machine as the system under test: contaminated results. Run from a separate host.
- Using `sleep` as pacing in an arrival-rate scenario: unnecessary. Let the executor pace.
- Unique-data endpoints given the same payload by all VUs: caches and conflicts distort results. Use per-VU data (`__VU`, `__ITER`).

## Review
- [ ] Thresholds encode the SLO and the run exits non-zero on breach.
- [ ] The executor model matches the traffic being simulated.
- [ ] Test data is loaded once and varied per VU.
- [ ] Target and secrets come from env, not hard-coded.
- [ ] A smoke run is part of CI.
