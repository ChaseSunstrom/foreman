# Foreman: brainstorm

Open-ended requests get ideas from several independent angles before any planning, so the work isn't limited to whatever comes to mind first. State changes go through `fm`.

1. **Classify and capture.** Say "Treating this as open-ended: brainstorming first." `fm capture "<verbatim request>" --type RESEARCH --tier M`, then `fm focus` it.
2. **Context pack** (main thread, ≤ 1,200 words, saved to a file in your scratchpad; the brainstormers see only this):
   the user's words verbatim and any CONTEXT/MUST/NEVER lines · what the project is (README's first paragraphs) · stack and entry points · top-level tree (depth 2, trimmed) · last 10 commits · test/build status (run them) · open Foreman queue and inbox titles (`fm state`) · known limitations, TODO/FIXME counts, recent failures (`fm log`/ledger) · constraints (budget, what must not change).
3. **Fan out**: `fm ideas --pack <file> [--lens L ...]` runs one sub-agent per lens in parallel, each a fresh `claude -p` session with no tools and no MCP servers (a Claude Code subagent can't be tool-less), and saves each answer under the project's `research/brainstorm-<time>/`. Lenses (default eight: user value, unspoken needs, delight, capability map, approaches, reliability, simplicity, bold bets; add `performance` or `security and safety` when the request is about them). A broad request with a concrete target ("a ton of benchmarks", "interop with no caveats") runs just `--lens 'capability map' --lens approaches` before its plan, so the plan covers the whole space, not the first items that come to mind. The user's own recent requests and corrections are added to every pack automatically; ideas come tagged by category, and `--deepen K` adds a yes-and round on the K biggest categories (use `--deepen 3` for anything open-ended). Prompt: `references/ideas-prompt.md`.
   **Super mode** ("fully featured", "everything", "all possible features", or the prompt note says so): `fm ideas --pack <file> --rounds 4` runs rounds that each see every idea so far and add only new ones (gaps, second-order improvements, combinations), stopping early when a round adds fewer than 3. Read the deduplicated index `ideas.md`, not every lens file. Every idea that survives grounding becomes a brief (not just a slate); build them in rounds, and after each build round super-brainstorm the improved project again with `--seen <each earlier ideas.md>` (so it goes past them) until a run comes back dry. Dry means grounded yield, not zero titles (lenses always produce some): when fewer than about three new ideas of real value survive grounding, record it with `fm decide` and stop; a cheap probe (two lenses, `--rounds 2`) is enough to tell.
4. **Merge, cluster, ground — all of it.** Dedupe across lenses, then cluster the ideas into capabilities (one line each: the capability and the idea titles in it). Ground every cluster, never a hand-picked shortlist: a grep or read per cluster, or one `foreman:fm-recon` per area in parallel for a big catalogue. An idea marked `near T-…` in ideas.md shares most of its words with that finished task, so check that task first. Already done → mark done; premise false → mark why; unclear → note it. Brainstormers never saw the code, so nothing goes forward ungrounded — and nothing is dropped silently (T-0364: 400 ideas became 17 rows and the rest vanished; the user asked to see every idea before any was turned down).
5. **Score** each grounded cluster: value 1–5, effort S/M/L, risk low/med/high, confidence, and your mark — build, or skip with its reason. Slate = the build marks in value-for-effort order: a normal brainstorm defaults to ≤ 8 items (at most one L); super mode, or a user who wants "most of them", gets every cluster not marked skip, built in rounds. Security findings and baseline-breaking bugs go first.
6. **Record.** `fm research add brainstorm-<date>` with the whole catalogue: every cluster, its ideas and lenses, grounding, score and mark. Turn the slate into briefs with one `fm intake` block (tags, `CONTEXT:` lines from the pack); the rest go to the inbox (`fm capture --source followup`).
7. **Show the catalogue, then go.** The user sees every cluster with your mark, not only the slate: a checklist page (Artifact) when it's long, so they can tick what to add or veto. Standard: ask one yes/no for the slate with that page. Full (`fm autonomy` says full): record the choice with `fm decide`, start the queue (`/foreman:next`), and put the page's link in the final report; the user's ticks later re-order the queue.
8. Close the brainstorm task with a `self` audit (`fm task audit ID self …`) and `fm task done`.
