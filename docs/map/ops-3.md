### Release, ship, CI and PRs

<details>
<summary>notes</summary>

- Review threads and merge train (T-1087, `fmpr.py`, through gh): `sampo pr threads ID [--pr N]` adds each unresolved review thread's first comment to the task as a step (redacted, defanged, marked untrusted data), keyed `[PR #N comment ID]` so a second run adds none. `sampo pr train [--task ID]` lists open PRs by number; a PR needs reviewDecision APPROVED and every check green, else it is skipped; drafts and PRs with no checks are skipped too; the task's `publish` grant (sampo ask ID publish) is required before any merge and is spent by the run (dropped from the task's allow, logged `grant_spent`; ask again for the next); each eligible PR's head is fetched (pull/N/head), merged onto the current base in a scratch worktree and put through the project's `sampo check` gates, then `gh pr merge N --merge --match-head-commit SHA` (the tested head, so a later push is refused); the first red re-test, conflict or merge failure stops the train with exit 1 and the merged PRs are still reported. The train runs each PR's code (conftest, Makefile, package scripts) with your environment: use it only on PRs from people you trust.
- CI watch (T-1052, `fmci.py`): `sampo ci-watch [--branch B] [--commit SHA] [--max-retries N] [--interval S] [--max-polls N]` polls gh run list (headSha, status, conclusion, url) for the watched commit only (HEAD re-read each poll, or --commit resolved to its full sha), so an older commit's run is never taken for this one; a failed run's --log-failed tail (last 40 lines, redacted, defanged, marked untrusted) becomes one FIX brief per run id; green exits 0, but a green run's failed non-blocking (continue-on-error) jobs are named and briefed once (T-1942); a failed run whose only failed jobs were cancelled with no steps (never got a runner) is no code failure: no brief, `gh run rerun --failed` and the new attempt is watched (runs are keyed by id and attempt), or, when gh can't rerun, exit 1 saying to rerun on GitHub or push again (T-2013); more than --max-retries failed runs, or max-polls without a finished run, exits 1 saying it gave up. It can wait a long time: run it in the background. Without gh (missing or logged out, T-1939) a github.com origin's runs come from the public API by head_sha (fixed host, no token, polls at least 75 s apart for the 60-an-hour limit) and the brief holds the failed jobs' annotations; a 401/403/404 (private repo, limit) ends it with gh's error and the code, and FOREMAN_NO_NET or a sensitive project keeps gh's error. T-2156: a 403 whose X-RateLimit-Remaining is 0 and whose ASCII reset is within MAX_RESET_WAIT (3700 s) instead says the hourly limit is spent and its HH:MM reset, waits (floored at the poll interval, not counted as a poll) and polls again, giving up after 3 consecutive waits; a watch on the public API takes a per-repo flock under the state dir, so a second watch waits instead of splitting the 60 calls (gh-authenticated watches never lock).
- `sampo release VERSION [--ui V] [--push] [--resume] [--dry-run]` (T-1188, `fmrelease.py`; Sampo's own repo only): release.py's ritual as 9 named steps (tree, check, bump, changelog, commit, release-check, canary, push, round), a checkpoint in the project's `release.json` after each; `--resume` continues from the first unfinished step (same VERSION), `--dry-run` prints the plan. `--ui V` is required when `mods/foreman-ui` changed since the last `Foreman X.Y.Z` commit. `--push [--remote URL]` needs the active task's `publish` grant (checked before any change, spent before the push, a `grant_spent` event), merges into the remote's main (origin by default) from a temporary worktree with `--no-ff`; a skipped push is never recorded, so `sampo release V --push` later runs only the push. The first run's `--ui/--push/--remote/--no-check` are kept for `--resume`; `--no-check` records the gates as skipped and such a release can't push; `--abandon` forgets an unfinished release (another version can't start over written changes until then). `release.py` is a thin wrapper over it.
- `sampo ship [COMMIT…] [--remote URL] [--test CMD] [--task ID] [--watch] [--check]` (T-1943, `fmrelease.py`; T-2323: in the scratch tree, `_affected_first` runs sampo check's affected selection (`fmcli.affected(..., since=main)`) before the full suite, and a red run stops the ship naming the failing classes, nothing pushed; T-2281: after the green test and before the push it writes the always-on footprint to the project's `footprint.json`, which `sampo doctor`'s footprint check holds as the lean ratchet: a metric past its band WARNs until a cut pays for it, and a metric that grew with no cut keeps its old value in the record, so the next ship can't absorb it (T-2358)): lands HEAD's commits the remote's main lacks (git cherry, by patch, after `refs/foreman/shipped`, the last commit it shipped, when that is an ancestor of HEAD: T-1945) or the named ones: fetches main, cherry-picks them in a scratch worktree at the fetched head, checks their files match the last pick, runs the test there (--test, remembered in git config foreman.shiptest for the next ship: T-1950; else sampo check), fetches again and pushes HEAD:main only if main is still an ancestor, spending the active task's publish grant, or with `--task ID` that task's, closed or active, so a finished task ships without a separate ship task (T-2007) (spent before the push, given back if git push fails; sampo release --push shares it); any failure pushes nothing and keeps the grant, the working tree is never touched, and
  the scratch worktree is always removed. Prints the pushed sha for `sampo ci-watch --commit`; `--watch` watches CI on it in the same job and exits with the watch's code (T-1946). A failed write of the shipped ref after the push only warns (T-1951). `--check` pushes nothing and needs no grant: exit 0 when main has those commits' changes (by patch; the default picks when none are named), 1 naming each one it lacks, so a ship task's criterion stays true after later ships (T-1960). A remote or commit that reads as an option is refused. Run it in the background. Its test run is marked (meta `ship_testing`) and waits for a live full `sampo check` or ambient run first; a full `sampo check` on another tree waits for it (T-1978).
- PR threads and merge train (T-1087, `fmpr.py`): `sampo pr threads ID [--pr N]` turns the PR's unresolved review threads (GraphQL reviewThreads) into task steps, each once by its exact step prefix, path and body redacted and defanged as data. `sampo pr train [--task ID]` takes approved, non-draft PRs whose checks are all green (an empty rollup is not green) in number order: each head merged with origin's base in a scratch worktree, the project's gates run there, then `gh pr merge N --merge --match-head-commit <tested sha>`; it stops at the first red re-test, conflict or merge failure and always reports what merged. It needs the task's `publish` grant, spent per run. The train runs each PR's own code (conftest, Makefile, package scripts) with your environment: use it only on PRs from people you trust.

</details>

### Night, drive and autonomy

<details>
<summary>notes</summary>

- Run contract (T-1158, `fmcontract.py`): `sampo contract --until HH:MM [--usd N] [--tokens N] | off | receipt` keeps meta `contract` {until, usd, tokens, started, tokens0}. `over(p, held=)` returns time/spend/tokens once a bound is reached and freezes it (`held` writes meta without re-locking: the Stop hook calls it under its own lock and fails open). Spend sums this project's `spend.jsonl` rows since the start (headless: `sampo run` records each session's `total_cost_usd` while a USD contract holds, one task at a time); tokens are this project's transcript totals from the cost cache (refreshed detached, at most once a minute). Past a bound the Stop drive and the forever loop stop (next_for drops the loop action), `sampo run` starts nothing and prints the receipt (tasks closed, spend, tokens, the bound). A startup or clear SessionStart after it ended keeps the receipt (`contract_receipt`) and drops the contract.
- Forever loop (T-1057, `fmloop.py`): `sampo loop on|off|status|round|yield N` keeps meta `loop` (on, round, dry, started, last, history). With it on, `_next_for` returns stage `loop` instead of idle when the queue and inbox are empty, and the Stop drive continues into the round once per round started (key round+brief count, within DRIVE_MAX, waiting while `_pace()` says usage is ahead). `sampo loop round` prints what shipped since the last round, the `sampo ideas` line with `--seen` for the newest 6 earlier ideas.md and the steps (T-1966: while `fmbudget.degrade` drops optional work, usage pace or the spent risk budget, step 2 drops sampo mission and sampo ideas for ideas made in the main thread); `sampo loop yield N` records the grounded yield once per round (T-1986: a dry yield while `fmbudget.degrade` drops optional work leaves the dry streak as it was and says so, since no fan-out ran; T-1990: the brief's step 5 says it too); while a round is open (no yield) a plain `sampo loop round` shows its brief again and changes nothing (T-1153), and `sampo loop round --next` (what sampo next says for a drained open round) gives it the count of tasks made since it began and starts the next, and 2 rounds in a row under 3 turn it off with a decision.
  `tally` (T-2011) gives "N rounds, M tasks closed since DAY" for this run (rounds since meta `from_round`, set by a fresh `sampo loop on`; distinct `task_done` events since `started`): in the stop decision, `sampo loop off` and `sampo loop`. While looping, a closed task or a started round resets the drive count, so DRIVE_MAX stops spinning, not long rounds. `sampo ui` carries `loop`; the pane and band show `∞ round N`. T-2073: `sampo loop round`'s Surfaces line names every top-level area and, from `lag(p)`, the files recent work would normally have brought along but didn't, learned from git history (`fmmap.drift`: co-change rate, updates owed), defanged, one line each, 'unknown' without git.
- Risk budget (T-1080, `fmrisk.py`): today's (UTC) ledger spends points: a guard block in a destructive category (rm-outside, git-destructive, system, credentials, self-authorize, pipe-shell, confine) 1, a close whose linked tests failed (close_affected exit ≠ 0) 2, a Revert commit since midnight 3. Past the cap (6, meta risk_cap), `c.effective_autonomy` steps down a notch (full → standard, standard → slow), `fmbudget.degrade(p)` names it so optional work waits, and `sampo next` says why; the next day restores it. `sampo risk` shows it; `sampo risk set --day N --because` is user-only (the guard's USER_ONLY_FM): the braked can't lift the brake. Every autonomy reader goes through effective_autonomy (sampo decide --ask then queues the ask instead of self-deciding), and every degrade() caller passes the project. It brakes Sampo's own autonomy decisions; it is not a guard: `sampo task set ID approved=true`, a re-tier or `sampo pause on` still move a task (each logged). One read per process while the ledger is unchanged (about 20 ms cold). T-1875: `fmrisk.collisions(p)` groups the last 7 days' guard_block events by rule (category when unruled), most first, with the newest detail and `fmguard._hint`'s rewrite; `sampo risk` lists the top 8, rules that spend risk first (T-1972; JSON `collisions`), and SessionStart's `Watch:` line adds `collision_line` (the rule, its count, → sampo risk; T-2117) for a rule hit 3+ times. Report only: CAP and WEIGHTS stay.
- Night queue (T-1046): `sampo night` adds a "queue" job when an unblocked S/M task is queued: `sampo run --fit --max 2 --wait 0 --max-usd <the night's remaining budget>`, planned only when its estimate fits the night's limit. `sampo run --max-usd X` runs one task at a time with `claude -p --output-format json`, records each session's total_cost_usd through fmbudget, and stops starting tasks once the run's spend reaches X (a single task can overshoot it). The night event holds the task ids closed since it began; `sampo digest` names them.
- Night gardening (T-1071): `sampo night` runs two free jobs: compost (`sampo tidy --apply --lanes-only`: worktrees and branches of done or dropped tasks only; an unmerged branch keeps its lane_branch) and consolidate (`sampo recall --lessons --consolidate --capture --from-night`: lessons grouped by token Jaccard ≥ 0.6 with the same negation words, `keep <id>` named, nothing retired; one open CLEAN task at most).
- Repeat-session skip (T-1825, `fmserve._repeat_key`): `sampo run`'s serial loop keys each session's start on the worktree id, the task's newest evidence line when it is a failed run (timestamp aside) and the steps and criteria done; a session that ends with the same key moved nothing but its own failing run, so the task is blocked with that check named (`block()`, then the next task) instead of buying another of its SESSIONS_PER_TASK. No git or a passing newest run: no key, no skip. `_fingerprint` now counts the first evidence line too (it counted "\n- ").

</details>

### Crash, snapshots and rollback

<details>
<summary>notes</summary>

- Crash damage (T-0268, pass 1): sampo doctor's `integrity` check scans Sampo's repo and every project root for zero-byte loose git objects (object names only, older than 5 s: git's in-flight tmp_obj_* files and an object being written aren't damage) (what a crash mid-write leaves; git then fails on any command that reads one), zero-byte briefs and state JSON that no longer parses, and names each; `sampo doctor --repair` moves the empty objects into `state/quarantine/git-objects-<time>/` (never deletes; across filesystems too, each failure reported; git rewrites any the working files still hold) and touches nothing else. sampo check runs doctor as a gate, so the next gate run after a crash says so.
- Crash hygiene (T-1405): the long verbs (check, code, release, bench, sentinel) write every thread's stack to `state/logs/stacks/<verb>-<pid>.txt` on SIGUSR1 and once after `FOREMAN_STACK_AFTER` seconds (30 min); an empty file is removed when the verb ends, a killed verb's empty one at the next long verb's start, and sampo tidy prunes dumps older than 14 days. A Sampo commit (`sampo task finish --commit`) that git refuses over `index.lock` removes the lock only when it is over 10 min old, no process has it open (an fd on its inode, any name or cwd) and no git runs with its cwd in the repo (Linux /proc; elsewhere it's only named); a git of ours it can't inspect keeps the lock, another user's or a non-git unreadable process doesn't (under hidepid=2 others' processes don't show); the lock is re-stat'd just before removal, and the removal logs an `index_lock_removed` event and retries once. sampo doctor's `lock probe` has a child hold an flock on a probe file in state/ and fails, naming the filesystem, when this process can still take it (that proves exclusion between processes on this host only).
- `sampo fsck [--fix]` (T-1667, in fmdoctor): read-only, every project, each line naming its project; open tasks' lanes whose folder, gitdir record or branch is gone (the `sampo lane rm` hint only for the current project), `*.pid` locks in state/ an hour old or more whose process is dead or that hold no pid, `*.jsonl` journals whose last line has no newline or isn't JSON (the last 64 KB, read twice before it's called torn), state JSON files (state/ and each project's top level, under 1 MB) that don't parse (T-1669), and either one it can't read; lib-sources, snapshots, quarantine, outputs and caches skipped, symlinks and FIFOs never opened; exit 1 on any. `--fix` (and sampo doctor --fix) removes only the stale locks, each re-checked first, and is refused outside the initial PID namespace (a sandbox's os.kill can't see a live holder); flock `.lock` files are never removed.
- Work snapshots (T-0884): before a Bash command that discards uncommitted work runs (`git reset --hard`/`--merge`, `checkout -f`/`--`/a path that names no commit, `restore` of the worktree, `clean -f`, `switch -f`/`--discard-changes`, `rm -f`, an `--abort` of merge/rebase/cherry-pick/revert/am, `worktree remove --force <dir>`, `stash drop`/`clear`; `fmguard.discards_work`, the guard's own tokenizer, following a `cd` before it, `-C` with `~`/`$VARS`, `sh -c` text, never heredoc bodies), the PreToolUse hook saves it under `refs/foreman/snapshots/<UTC stamp>-<sha7>[-stash]` (`fmcore.snapshot`: the working files, untracked included and ignored not, as a commit when they differ from HEAD; or the stash commits), in every session, never blocking, within 3 of the hook's 5 s (`SNAPSHOT_S`; past that, or on a git failure, the note says nothing was saved), and tells Claude the sha and the restore line (`fmcore.restore_line`: `git -C <top> restore --source=<sha> --worktree -- :/`, or `stash apply <sha>`; newer files are left alone). `sampo snapshots` lists the project repo's saves newest first; `sampo tidy --apply` deletes ones older than 14 days. Limits: `--git-dir`/`--work-tree` and commands python spawns aren't followed; an untracked non-ignored secret rides along in the local ref for those 14 days (a `push --mirror` would carry it).
- Rollback (T-1085): `fmrollback` snapshots BACKUP_PARTS of every project into `state/snapshots/<old>-<ts>.tar.gz` (a detached child at the first SessionStart after a version change; `.part` then rename; a manifest of sha256s; 3 kept, pre-rollback copies in their own pool of 3). `sampo rollback --yes` extracts to a temp dir with filter='data', checks the manifest, replaces files under `c.lock`, skips ledger files, re-applies live consent meta (standing, approvals, autonomy, pause, trust) and each brief's allow/approved, and logs `rollback`. `fmguard.USER_ONLY_FM` holds every user-only sampo command (prefix-matched flags).
- Small verbs (T-0960): `sampo oops` names the newest work snapshot and its restore line; `sampo oops --apply` restores it after snapshotting the files as they are. `sampo round close` tags HEAD `round-N` (one past the highest) and lists the done tasks its commits name (subject or `Foreman-Task:` trailer, reverts skipped) since the previous round tag. `sampo show X` routes: a task id → `sampo task show`, an existing FILE[:LINE] → `sampo why`, other words → `sampo recall`. `sampo release-check` runs `sampo doctor` and `sampo demo` on this checkout with a temporary HOME and `FOREMAN_STATE`, then the docs' runnable fences (T-1519, above; trusted like tests, not sandboxed), exit 0 when all pass (`fmdemo.cmd_release_check`). `sampo sensitive suggest` prints the paths that suggest a sensitive repo (`.env*` but not `.example/.sample/.template`, `*.pem`, a `secret(s)`/`prod(uction)` path part; `fmcli.sensitive_signals`) and sets nothing. `sampo outcomes --readme` prints "N of M closed tasks held; K ungraded" (ungraded: done without a recorded verification grade).

</details>

### Cards and library

<details>
<summary>notes</summary>

- Card library growth (T-1037, `fmlib`): `sampo lib gaps [--root DIR]... [--json]` lists dependencies no card covers across registered projects (or the given roots; a missing root is an error), most-used first; `sampo lib draft NAME --area AREA` stages a skeleton in the state's lib-drafts; `sampo lib admit PATH|NAME` reads the staged card once (no symlinks), runs the card lint and an untrusted-text check on those bytes (curl/wget piped to a shell or python, bash <(curl …), ignore-previous-instructions, --no-verify, disabling tests/checks/hooks/guards, rm -rf ~ or /; exempt only where a governing never/avoid/don't directly precedes the match, or inside an Avoid bullet's quoted example), and writes it with O_EXCL under the cards folder only (kebab-case area and name).
- Import-matched cards (T-1036): `sampo map` keeps every detected card's `dep:` signals (and up to 40 dependency cards past the top 8); `fmlib.cards_for` reads the edited file's first 64 KB plus the edit's new text (`imports_of`: Python modules with a distribution-name alias table, JS/TS packages incl. scoped ones, Rust crates, Go import paths; relative imports and std left out), returns the import-matched cards (score, then name) then `card_for`'s pick, at most two, each injected once per task; `sampo audit prep` appends the Review checklists of the cards a task's edits used (`fmlib.card_review`); `sampo lib stats` counts `card_injected` events per card.
- Edit-time stack cards (T-0949): the PreToolUse hook, on a Write/Edit/MultiEdit/NotebookEdit under an active task, picks the map's best card for the file from `map.json` alone (`lib_cards`: each suggested card's area, score and file/ext signals; `fmlib.card_for`): a card whose file glob or extension matches, a framework card before a language card, then the higher score, then the name. When this task hasn't had that card yet (an `enforce` ledger event of kind `card_injected`, written before the note goes out, so a lost output never repeats it), it adds the card's Avoid section, cut at a whole bullet to at most 700 chars with '…'. No Avoid section, no such card or a malformed map adds nothing, and a failure never blocks the edit. Off with `FOREMAN_NO_CARDS=1` or `sampo lib inject off` (project meta `lib_inject`). `sampo doctor -v` shows the enforcement line: 7-day counts of validator blocks, merge refusals (`sampo lane merge`'s red or unrunnable criteria, also `enforce` events), waived merges (`lane_unverified`) and injected cards. Review fixes: a non-language card's ext that a language card also has is stored as `lext:` and ranks after that language's card (a topic card like go-concurrency never shadows lang/go for every .go file); the once-per-card-per-task memory is `cards.json` in the project's state (the last 50 tasks), so later edits read a few bytes, not the ledger; `sampo lib inject` with no word never creates a project; a merge the guard refuses is a `merge_refused` enforce event too. T-0980: the map keeps up to 3 language cards past the top 8 (Sampo's own top 8 were all claude-code cards, so no .py edit ever got the python card).
- Cards at prompt time (T-0977): a UserPromptSubmit whose text names a stack card outright (whole word, longest first: react-hook-form before react; hyphens also match as spaces) gets one line naming up to 3 of them with the `sampo lib show … --section avoid --section verify` call, once per session per card (`_first_time`), and a `lib_named` ledger event; card names that are everyday words (make, go, just, express, solid …: `fmlib._COMMON`) never match. The names come from `state/lib-names.json`, rebuilt only when the card count changes, so a prompt never parses the cards (about 30 ms cold, 1 ms warm). `sampo doctor -v`'s enforcement row adds cards named and cards read (sampo lib show) over 7 days.
- Project map: `sampo map` keeps `map.json` in the project's state dir (gates from `sampo check` and the project's own files, layout, entry points, the most-changed files over 180 days, and test ↔ source links by name within a language, e.g. `test_guard.py` → `fmguard.py`, plus every file under a top-level folder other than its own that a test names as a string literal, e.g. `test_design_lint.py` → `site/`, T-2086), rebuilt when HEAD moves (`--rebuild` forces it); `sampo impact PATH` lists the tests linked to a path and the files that mention its module; `sampo focus` adds the likely tests for the brief's scope to its Related section. The intake skill grounds from these before reading code.

### Pane and UI

<details>
<summary>notes</summary>

- Speedrun splits (T-1078, `fmwatch.splits`): the pane's task block shows each stage's time for the active task against the median of 3 or more closed tasks of its type and tier, in green under and red over (beyond ±10%); `sampo ui --json` active.splits. In the history, `b` steps back one entry and `l` returns to live; while scrubbed, an "as of HH:MM (N back) · press l for live" row heads the entries up to that point.

### Sampo Code

<details>

### Running it

<details>
<summary>notes</summary>

- Headless (a server, no terminal open): `sampo serve` in a repo runs Claude Code Remote Control there as a systemd user unit (`~/.config/systemd/user/foreman-serve-<slug>.service`; its output, which includes the session URL, is discarded and errors go to the journal), survives logout and reboot (it enables linger, or warns), restarts on failure with a 5-in-10-minutes breaker (a restart reconnects its sessions), and puts the project in full autonomy with drive on; send requests from claude.ai/code or the Claude app. Starting it needs your yes (`sampo ask ID remote`); `claude` is found on the saved PATH at every start. It uses your default permission mode unless `--permission-mode` is given (sensitive repos: `default`, approve from the phone). `sampo serve status` (unit state, repo, active task; the last journal lines, URLs hidden, when it's down; `sampo doctor` warns on a dead unit) · `sampo serve stop [--all]` (restores autonomy and drive; uninstall stops every unit). Claude Code must trust the repo root itself first (open `claude` there once; a trusted parent folder doesn't count).
  `sampo run` instead works the queue in fresh `claude -p` sessions, one task each (drive scoped by `FOREMAN_DRIVE_TASK`), skipping tasks that wait on you; a usage limit is waited out with backoff (5 min doubling to 1 h per wait, `--wait` hours in total, default 6, each wait logged) and the task retried; it stops on no progress, any other nonzero exit (login, crash), the wait budget, the per-session timeout or two sessions in a row that end blocked or unfinished in a lane (T-0434: a breaker that only stops, never retries; a usage limit doesn't count); a task with no progress, or still unfinished after its sessions, is blocked with that reason first, so the next run takes the next task (T-0955); it re-execs itself once under `systemd-inhibit --what=sleep:idle` when that's on PATH and logind answers (env guard `FOREMAN_INHIBITED`) so the machine doesn't sleep mid-run; `sampo night --print-timer` prints a systemd user timer + service and a crontab line for a nightly `sampo night` and installs nothing; it logs to `state/logs/run-<slug>.log` (redacted), and refuses while `sampo serve` runs in the same project.
- Disable: `claude plugin disable foreman@foreman` (Claude Code works normally). Drive only: `sampo drive off`.
