# Site hero poster: build.py draws the proof chain from site/data/stats.json as an inline SVG poster, the hero's first paint and its fallback
## Raw request
> Site hero poster: build.py draws the proof chain from site/data/stats.json as an inline SVG poster, the hero's first paint and its fallback
## Interpretation
site/build.py gains a poster step: it reads site/data/stats.json and draws an inline SVG of the proof chain (tasks done, evidence, proofs, commits as stations along one track, each sized by its total, the real numbers as text) as the hero's first paint in the built index.html. The same SVG is the still fallback T-1610's WebGL scene sits over. The site is built by python3 site/build.py, which Claude Code runs like any command, so no new verb is needed.
## Assumptions (confidence)
## Acceptance criteria
- [x] the built index's hero is an inline SVG poster (role=img, an aria-label naming the real totals from stats.json, no external host); a changed stats.json changes it — verify with `python3 plugin/tests/run.py test_site_hero`
## Non-goals
## Approach (options → choice → why)
Options: a PNG poster rendered once and committed (needs a rasteriser or a browser, and goes stale); CSS-only bars (no chain, weak at small sizes); an inline SVG generated by build.py from stats.json. Choice: the inline SVG: stdlib only, it changes with the stats, its numbers stay real text for screen readers (role=img plus aria-label), and it keeps the site's no-third-party rule (T-1411).
