## Non-goals
## Approach (options → choice → why)
1) A new module, plugin/lib/sampo/live.py. It reuses settingsserve's auth (the one-time token, the cookie, the Host check, the CSP) by importing its helpers, not copying them. Collectors return the snapshot from the research note live-schema, each one fail-soft. /api/state returns a snapshot; /api/stream sends Server-Sent Events every 2 s. Static files are served from plugin/web/live/. `sampo live` starts the server, and `sampo live --url` reprints the URL. Likely outcome: a cheap, read-only feed of everything running. Fails if: a collector is slow; each has a short timeout and a cache of a few seconds.
2) use what exists: `sampo ui --json` (the pane's view model) as the whole feed. Likely outcome: tasks and session state, but no models, GPU, jobs or flows. Fails if: the user asked for local models and the flows between them.
3) do less: a static HTML file regenerated by the night job. Likely outcome: no live motion. Fails if: "constantly running" and the animations need a live stream.
Choice 1 (80%): the feed is the hard part, and the page only renders it; the auth is reused, not rewritten.
