# Brainstorm — lens: simplicity

- **Delete the stage machine's seven names from the UI** — CLEAN — value 4 — effort S — risk low — category: simplicity
  Why: the user said "L, T, M mean nothing as letters"; the pack shows seven stages (captured→…→closing) plus tiers, steps, and criteria. Assumption: users only act on three states: planning, working, needs-you.
  Done when: every surface (band, pane, statusline, `fm ui --json`) shows at most three state words, with a test that fails on any other.

- **Make `fm task new "one sentence"` the only entry point** — FEATURE — value 5 — effort M — risk med — category: capture
  Why: ~18 bookkeeping calls per task and planning ceremony is the next biggest call count (task_set 1290 events). Assumption: Haiku can infer size, criteria, and steps from one sentence, and the user edits only if they disagree.
  Done when: one command creates a planned task from a sentence, and a trivial-task fixture reaches "ready" with zero further fm calls.

- **Collapse 45 subcommands to a visible "five verbs" surface** — CLEAN — value 4 — effort M — risk low — category: surface area
  Why: T-0094 (help tiers) is in the inbox, and the user wants quiet output. Go past tiering: aliases for the other 40 stay, but only five (add, plan, go, done, status) are documented, completed, and suggested in hints.
  Done when: `fm help` prints five lines, and no hint or rule text mentions a command outside those five.

- **Replace the rules file with a generated one-liner per gate** — CLEAN — value 4 — effort M — risk med — category: instructions
  Why: T-0085 rules diet is open, and ~43 always-on lines cost every session. Generate each rule from its gate's refusal message so rule and enforcement can't drift.
  Done when: the rules file is generated by a build step, contains at most 15 lines, and a test fails if a gate has no matching line.

- **Add a single "Foreman is quiet" master switch** — FEATURE — value 3 — effort S — risk low — category: noise
  Why: the user repeats "clean up your output in general" and "quiet output"; the pack has toasts, chimes, mascot, spinner names, summary lines, and hints, each configured separately. Assumption: one switch with levels (off/quiet/full) beats per-feature flags.
  Done when: in quiet mode, a full task run emits no toast, chime, or hint, only the needs-you line and the final result.

- **Make "done" the default and ceremony opt-in by size** — PERFORMANCE — value 5 — effort M — risk med — category: speed
  Why: close-out is 42 of 125 hours and gates 18.8 hours, with one project's `cargo test` at a median of 8 min per task. Assumption: a one-file, non-core change needs no plan card, no audit, and only affected tests.
  Done when: a one-line doc fix completes in under 3 fm calls and no full test run.

- **Wild: Show a task as one sentence that rewrites itself** — FEATURE — value 3 — effort M — risk low — category: delight
  Why: wild; replaces stepper, bars, criteria, and audits in the band with a live plain-English line such as "Fixing the login bug — tests running, 2 of 3 done." Assumption: Haiku summarizes from `fm ui --json` and is cached per state change.
  Done when: the band shows one sentence that changes within 2 s of a step change, with no extra model call when the state is unchanged.

- **Wild: Offer a "just do it" mode that hides Foreman entirely** — FEATURE — value 4 — effort L — risk med — category: autonomy
  Why: wild; the user is usage-sensitive, wants full autonomy, and hates being handed commands. The mode runs the whole cycle invisibly and shows only a morning-style result: what changed, what's proven, what needs a yes.
  Done when: a run of three queued tasks produces exactly one final summary and zero mid-run UI beyond the spinner.

- **Wild: Auto-delete features nobody used** — CLEAN — value 3 — effort M — risk med — category: pruning
  Why: wild; 45 subcommands, 13 hooks, and many rules; the ledger knows what gets called. Quarterly, Foreman lists commands, rules, and playbooks with zero uses in 60 days and proposes removing them.
  Done when: `fm prune` outputs a list built from ledger counts, and applying it removes the items and passes the test suite.

- **Merge inbox, queue, and plans awaiting approval into one list** — CLEAN — value 4 — effort M — risk low — category: mental model
  Why: the dashboard has separate cards for the queue, inbox, and plans awaiting approval, and the open inbox holds old items (T-0077…T-0094) that the user rarely sees. Assumption: a single ordered "things" list with a status word is simpler to scan and capture into.
  Done when: the dashboard shows one list, and capture, approve, and reorder all act on it.

- **Wild: Let the user answer one question a day to steer everything** — FEATURE — value 3 — effort S — risk low — category: taste
  Why: wild; the user says brainstorms miss "things I want but don't know how to say." Foreman asks a single either/or question daily ("faster or safer?") and tunes brainstorm lenses and ceremony from the answers.
  Done when: answering a question writes a preference that measurably changes the next brainstorm's category weights, verified by a fixture.
