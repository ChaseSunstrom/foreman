**Findings**

1. **`cat >> test.py <<'EOF'` blocked as "interpreter code driving Foreman's modules" (9×, core)**
   - Evidence: `fmguard.py:909-912`. `_drives_fm` searches `rest`, and `_python_units` puts every non-python heredoc body into `rest` (`fmguard.py:757,766`). A test file that contains `import fmcore` and `mutate(` as text therefore trips it. `_drop_data_heredocs` (`fmguard.py:414-434`) already removes such bodies, but `_interpreter_writes` applies it only to the `_INTERP` gate (`fmguard.py:968`).
   - Fix: run `_drop_data_heredocs` over `rest + starters` before the line 912 search. Add a test_guard case for `cat >> t.py <<'EOF'` with fm imports, followed by `python3 t.py`.
   - Effort: S. Confidence: medium. The example command is truncated, so I inferred the trailing interpreter call.
   - This is the same friction T-0171 targeted, and it only half-removed it.

2. **Edit script that names a state path is blocked state-direct, which can never be authorized (2×: skill-index.json, research/MEMORY.md)**
   - Evidence: `fmguard.py:978-984`. When `_proved_writes` returns None, every quoted path is a write target, and `_GUARDED_BY_PATH` (`fmguard.py:583`) includes state-direct. A script containing `global s` fails the proof (`fmguard.py:805`).
   - The docstring at `fmguard.py:965-967` says unprovable text should need core, "rather than never-authorizable state-direct". The code does the opposite.
   - Fix: in the unproven branch only, map state-direct to core.
   - Effort: S. Confidence: medium. Trade-off: a real script write to state becomes user-approvable.
   - Optional: let `_open_targets` accept `global`.

3. **`cp … && git checkout -…` in Foreman's checkout is blocked as a core tree write (3×)**
   - Evidence: `fmguard.py:1661-1663` returns the whole checkout for any `_GIT_WORKTREE_WRITES` subcommand, including `checkout -- <pathspec>`. `test_guard.py:838` locks in that a pathspec on `plugin/lib` is core.
   - Fix: for `checkout` or `restore` with explicit pathspecs after `--`, return only those paths, which the normal classifier then judges. Branch switches stay a whole-tree write.
   - Effort: M. Confidence: low-medium. The command is truncated, and a bare `git checkout -` is a branch switch and correctly blocked.

4. **The digest hides why tool calls failed**
   - Evidence: `fmhooks.py:1115-1116` records `error`, but `fmfriction.py:94-96` groups by target truncated to 90 characters and drops `error`. All 5 Read failures show only `/tmp/…/scratch…`.
   - Fix: group by `(tool, error[:60])` and keep the tail of the target.
   - Effort: S. Confidence: high.

5. **The "40× the drive ended a turn" line isn't a stop**
   - Evidence: `fmhooks.py:1426-1430` returns None and emits only an event plus a systemMessage. It is the intended wait for background work. `fmfriction.py:102` still labels it friction, and the `running[:5]` dedupe (`fmhooks.py:1427`) re-counts whenever the list changes.
   - Fix: drop it from "nudges and drive stops", or count distinct tasks.
   - Effort: S. Confidence: medium.
