1. **Answer.** Four of the five friction points trace to small, local causes. The guard leaves a variable unknown when its value starts with `~`. The argparse quirk comes from using `parse_args` on a `nargs="*"` positional. `fm task ac` has no way to edit a verify command. The `#T-0328` token is stripped by `_title`, and that part is by design. I did not trace the `S=…; (cmd > $S/app.log &)` block to a specific cause.

2. **Findings** (all read from the code, none run)

- **Guard, `D=~/…` stays unknown (FIX, S; high that the cause exists, medium that it caused your block).** `_track_vars` drops any value matching `[*?\[~\s]` (`plugin/lib/fmguard.py:1268`). `D=~/projects/foreman-desktop; mkdir -p $D && cd $D && tar xf -` therefore leaves `$D` unknown. `_moved` then treats the cd as `lost` (`fmguard.py:1089`). `_target_cats` guesses any path named in the command (`fmguard.py:1172-1205`), which includes the Foreman checkout.
  - **Fix:** in `_track_vars`, expand a leading `~` or `~/` to `ctx.home` before that test. `ctx` must be passed in.
  - **Tests:** the existing EXTRA forms `D=~; rm -rf "$D"` and `D=~ ; rm -rf "$D/"` still block, because `D` then resolves to HOME. Add these to FORMS or EXTRA in `plugin/tests/test_guard_diff.py` (these two are new):
    - `D=~/x; mkdir -p $D && cd $D && tar xf -`
    - `D=~/x; (cd $D; rm -rf ~)`
  - The `rm-outside` rows on `foreman-desktop/src-tauri/icons/android` are a different case. Those used an absolute path under `--allow rm-outside`. I did not trace why they still block.

- **Guard, `S=…; (cmd > $S/app.log &)` (low confidence).** `_prefix_vars` should resolve this (`fmguard.py:1153-1169`). It keeps a name only if `counts[k] == 1`. `counts` counts every bare word matching `[A-Za-z_]\w*`, including path segments and flags. A command containing a standalone `S` (for example `-S`) or a second `S=` makes `S` unknown. I could not see the exact command, so this is a candidate cause.
  - **Fix:** count only assignment targets, not every word.

- **argparse `fm session send ID --json -- MSG` (FIX, S; high).** `session` and `claude` declare `rest` with `nargs="*"` (`fmcli.py:2572`, `fmcli.py:2586`), and `main` calls `parse_args` (`fmcli.py:2643`). Positionals are consumed in one block, so tokens after an interleaved option become extras and the parse fails.
  - **Fix:** call `parse_intermixed_args` at `fmcli.py:2643`. Add a test next to `test_claude.py:165`. I have not checked that `parse_intermixed_args` accepts this parser, since it has subparsers.

- **No way to edit a criterion's verify command (FEATURE, S; high).** `task ac` accepts only `add` and `check` (`fmcli.py:2181`). `task_ac` (`fmcli.py:989-1007`) has no edit branch. `finish` runs whatever `verify_of` returns as a shell command (`fmcore.py:2248`, `fmcli.py:471-478`).
  - **Fix:** add an `edit` action that rewrites the verify tail with `--verify`. Optionally warn when the verify text starts with `typed:`, since `_lint_verify` reports a missing program only as "isn't on PATH". I could not confirm how your "typed: …" criterion was entered.

- **`#T-0328` dropped from the capture title (FIX, S; high).** `_title` strips every reference from the first line (`fmcli.py:120`, using `_REF_RE` at `fmcore.py:1315`). `cmd_capture` never uses the refs as `depends`, so the dependency is lost as well as the text.
  - **Fix:** strip only a leading or trailing `#T-…` token. Alternatively, record the refs as `depends=` in `cmd_capture` and say so in the output.
