**Verdict: changes needed.** `fm find` will crash or hang on an unusual untrusted tree. I could not run anything, so every finding below comes from reading the code, not from a run.

## lens: adversary
- HIGH — plugin/lib/fmfind.py:149-152 — `_files` follows symlinks. `getsize` and `open` resolve the link, so `x.py -> /dev/zero` reports size 0 and `f.read()` never returns (OOM). A symlink to a FIFO blocks forever in `open`. A symlink to `~/.aws/credentials` is read and scanned, and the finding reveals that file's existence and line. Git lists tracked symlinks, and `os.walk` lists links to files, so both paths hit this. Fix: `os.lstat`, require `S_ISREG`, and read `f.read((1<<20)+1)`. Apply the same checks to the `fmdocs._markdown` `isfile` check, the `fmtidy.stale_commands` Makefile read and `fmoutside._toml`. Confidence: confirmed by reading.
- LOW — plugin/lib/fmfind.py:149,427 — `fmmap.is_generated` skips a file whose first five lines contain "generated by" or "DO NOT EDIT". The secrets finder then skips it too, so a file with a leaked key and `# generated by` on line 1 is not scanned. Fix: skip generated files for code finders only, never for secrets. Confidence: confirmed.
- LOW — plugin/lib/fmfind.py:133 — git runs inside the untrusted repo with that repo's config. A `core.fsmonitor` setting there could execute code. Fix: `git -c core.fsmonitor=false -c core.hooksPath=/dev/null`. Confidence: plausible.

## lens: edge
- HIGH — plugin/lib/fmfind.py:133-134 — `text=True` decodes `git ls-files -z` output strictly. A tracked file named `caf\xe9.py` raises `UnicodeDecodeError` and kills the scan. A missing `git` (`FileNotFoundError`) or a timeout (`TimeoutExpired`) is also uncaught, unlike the sibling code in `fmdocs.py:23-26`. A crash exits 1, the same code as "findings found". Fix: capture bytes, use `os.fsdecode(...)`, catch `(OSError, subprocess.SubprocessError)` and fall back to the walk. Confidence: confirmed.
- MEDIUM — plugin/lib/fmfind.py:319, 309-329 (and fmoutside.py:125) — `_toml` catches only `TOMLDecodeError`. `tomllib.load` raises `UnicodeDecodeError` on a non-UTF-8 `pyproject.toml`, which is not caught. `.get` is called on unchecked types, so `project = "x"`, `optional-dependencies = []` or `"dependencies": [{}]` in package.json raises `AttributeError` or `TypeError`. A package.json nested about 100k levels deep raises `RecursionError`. `fmtidy.py:76` has the same flaw for `package.json` containing `[]`. Fix: wrap each manifest in `try/except (ValueError, TypeError, AttributeError, RecursionError)`. Confidence: confirmed.
- MEDIUM — plugin/lib/fmfind.py:32, 228 and :25 — two regexes backtrack badly.
  - SQL: `select\s.*\bfrom` is quadratic on a long line, so a 100 KB line of `select select …` inside a function takes about 10^9 steps.
  - C: `(?:[\w*]+[ \t*]+)+?` splits runs of `*` in exponentially many ways, so a column-0 line of 40 or more `*` in a `.c` file hangs.
  Fix: cap line length (skip lines over 2000 characters) and make the C def pattern unambiguous. Confidence: plausible.
- MEDIUM — plugin/lib/fmfind.py:133-137 — a directory that a parent repo's `.gitignore` excludes makes `ls-files` exit 0 with an empty list. The result is "Nothing found in 0 files", exit 0, a silent false negative. Fix: use the walk when git lists nothing, and say "0 files scanned" without calling it clean. Confidence: plausible (git behaviour not run).
- LOW — plugin/lib/fmfind.py:140 — outside git, `venv/` and `env/` are walked and scanned. Fix: add them to `SKIP`.

## lens: maintainer
- MEDIUM — plugin/tests/test_find.py — nothing covers a failure path: symlink, non-UTF-8 name or content, malformed manifest, no git, ignored directory, or "0 files" output. Each finding above needs a test that fails first.

- Findings are candidates, so a precision ceiling is accepted.
- Files over 1 MB, hidden directories and `fixtures` are skipped.
- Test files are never secret-scanned (:425).
- An import counts as declared if a declared name is a substring match.
- A crash exits 1, the same as "findings".
