# Foreman [![tests](https://github.com/ChaseSunstrom/foreman/actions/workflows/test.yml/badge.svg)](https://github.com/ChaseSunstrom/foreman/actions/workflows/test.yml) **The discipline layer for Claude Code.** Foreman makes Claude plan before it edits, prove its work with commands it actually ran, stay on one task at a time, and keep going through the queue until it's done or needs you, while a guard hook stops the commands you'd never want run in bypass mode. <p align="center"> <img src="demo/live.svg" width="960" alt="Claude Code with the foreman-ui mod: asked to fix calc.add, Claude plans task T-0001, edits the code, is refused a close until a red-then-green proof exists, proves it, closes and commits; the Foreman pane shows the task with its stage rail and progress, what is running now, the plan's steps and criteria, and live charts of the session's tool calls"> </p> <p align="center"><sub>Claude Code with the foreman-ui mod, recorded as it fixes a seeded bug: one typed request, the rest is Claude working through Foreman. Sped up where the model thinks; <a href="demo/live.mp4">MP4</a>.</sub></p> ## Why Claude Code is fast. Left to itself it also fails in familiar ways: it edits before it understands the problem, says "tests pass" without running them, chases every new idea halfway through a task, loses its place after `/compact`, and in bypass mode it will run the one command you'd never type.
