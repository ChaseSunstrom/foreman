## Which reliability problems do developers report with AI coding-agent harnesses (Claude Code, Codex, Cursor, Aider, Cline) as of late 2026, such as context loss in long sessions, hallucinated or incorrect edits, unpredictable behavior across model updates, and flaky tool calls or sandboxing?

## What missing features and capabilities are developers requesting for these harnesses and plugins, such as better memory and persistent project context, multi-agent orchestration, verifiable testing and review loops, permission and security controls, and IDE/CI integration, and which developer communities, companies, or maintainers are asking for them (e.g., GitHub issues, Hacker News, Reddit, developer surveys)?
- ✓ [read] Developers want persistent cross-session memory in Claude Code. Issue #14227 (opened Dec 2025) asks for a local memory store, `claude --continue` / `--session <id>`, and sync with claude.ai memory. The author says CLAUDE.md is "manual and limited." The issue has about 10 👍. A stale bot closed it as "not planned" in May 2026, and it was locked on Oct 14, 2026. That closure was automated, not a maintainer decision. — https://github.com/anthropics/claude-code/issues/14227 "Claude Code starts every session with zero context. There is no memory of previous sessions, previous work, or accumulated understanding of the user's projects and preferences." (community, 2025-12-16 (locked 2026-10-14); quote found) · single source
- ✓ [read] The same thread shows the gap being filled by third-party tools. Users posted MCP servers and hook-based memory projects (inspeximus, memory-ts, CogmemAi, mnemon, OMEGA and others) as workarounds. I did not verify what those tools claim. — https://github.com/anthropics/claude-code/issues/14227 "Users paying for Claude expect continuity across the product, not amnesia in the CLI." (community, 2026-10-14; quote found) · single source
- ✓ [read] Developers distrust agent output, and the demand is for verification. In Sonar's 2026 survey, 96% do not fully trust AI-generated code to be functionally correct. Only 48% always check it before committing. 64% have started using autonomous agents. — https://www.sonarsource.com/company/press-releases/sonar-data-reveals-critical-verification-gap-in-ai-coding/ "only 48% state they always check their AI-assisted code before committing it" (secondary, 2026-01-08; quote found) · single source
- ✓ [read] Qodo's 2026 report (developers and engineering leaders) names reviewing and validating AI code as the top delivery bottleneck. It also finds agents don't reliably follow written standards even when given context, with 65.4% saying agents don't always follow them. Both points support requests for enforceable project rules and review loops. Qodo sells code-review tooling, so the report is vendor research. — https://www.qodo.ai/state-of-ai-code-quality-report/ "Both groups identified the same top delivery bottleneck: reviewing and validating AI-generated code." (secondary, unknown (page content suggests about Sept 2026); quote found) · single source
- ✓ [read] The Stack Overflow 2025 survey (published July 2025, page dated Dec 29, 2025) shows agents are not yet trusted. Trust in AI accuracy fell from 40% to 29%. The top frustration, at 45%, is "almost right, but not quite" output that makes debugging slower. The page says the agent revolution is "not yet" here. — https://stackoverflow.blog/2025/07/29/developers-remain-willing-but-reluctant-to-use-ai-the-2025-developer-survey-results-are-here "trust in the accuracy of AI has fallen from 40% in previous years to just 29% this year." (primary, 2025-12-29; quote found) · single source
- ✓ [read] Permission and security controls are a major ask. Academic researchers (arXiv 2604.13536, v5 Sept 2026) describe "YOLO mode" as a response to approval fatigue. They argue prompts should show filesystem effects instead of commands, and that users should set path-level access rules and review changes in one batch at the end. — https://arxiv.org/html/2604.13536 "They accept the risk because the alternative is answering hundreds of prompts per session." (secondary, 2026-09-16; quote found) · single source
- ✓ [read] Vendors are responding to approval fatigue with sandboxing and automated approval. OpenAI's Codex docs say "The sandbox reduces approval fatigue" and describe an "Approve for me" mode that routes eligible requests through automatic review. — https://learn.chatgpt.com/docs/sandboxing "The sandbox reduces approval fatigue." (primary, unknown; quote found) · single source
- ✓ [read] Sandboxes themselves are unreliable. Two Cursor flaws (CVE-2026-50548 and CVE-2026-50549, reported July 1, 2026) let a prompt-injected agent write a file it shouldn't and disable the sandbox. They were patched in Cursor 3.0. This supports requests for sandboxing that holds up against hostile input. — https://thehackernews.com/2026/07/critical-cursor-flaws-could-let-prompt.html "get the agent to write one file it should not be allowed to write" (secondary, 2026-07-01; quote found) · single source

The search snippet is the only evidence I have. The page could not be fetched, so there is no quote. This is the main multi-agent orchestration complaint I found. — https://claudeissues.com/issue/69283-feature-opt-in-context-inheritance-for-agent-spawned-subagents-inherit-context-f "inherit_context" (community, 2026-06 (unverified); unchecked: not a public https URL) · single source
