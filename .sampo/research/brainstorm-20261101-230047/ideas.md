## Kill it fast (the quickest test that would show it isn't worth building)
- Add a heartbeat so silence means "alive" — Grep last month's logs for a "silent but alive" misread; if no one ever asked "is it running?", skip it.
- Catch up missed runs once, coalesced — Count missed runs over 30 days; if fewer than 2 mattered, catch-up is dead weight.
- Answer PR review comments in a lane — Check the last 20 PRs; if fewer than 5 review comments needed a code-aware answer, drop it.
- Reproduce-first issue watcher — Hand-reproduce 10 recent issues; if under half reproduce without extra info, a watcher just produces noise.
- Fire onto a worktree, never the user's tree — Run `git worktree add` by hand on the repo; if setup (deps, env, ports) takes over 2 minutes, it won't work unattended.
- Add a drop folder as a file trigger — Ask whether you've dropped a file into any folder in the last month; if not, nobody will use it.
- Show a trigger inventory with cost and fire record — Run `crontab -l` and `systemctl --user list-timers`; if there are under 3 entries, an inventory is overkill.
- Switch branches and resume that branch's goal — Count branch switches per week that actually needed their goal resumed; if under 2, it's a gimmick.
- Test the project against new upstream releases — Check how many upstream releases broke you in the last year; if under 2, a weekly CI matrix already covers it.
- Wild: Offer to schedule what you do by hand every week — Review shell history for weekly repeats; if no command sequence appears 4 or more times, there's nothing to offer.
- Wild: Hold fires while the user is mid-flow — Measure how often a background fire actually interrupted you; if never, the hold is solving nothing.
- Wild: Commit triggers to the repo as reviewable standing orders — Ask one teammate to review a trigger file in a PR; if they'd say "just use CI config," it's redundant.
- Send a one-line weekly receipt per trigger — Check whether you read the last 3 status emails; if not, a receipt gets ignored too.
- Add a dead-man heartbeat to the timer — Dupe of 1: if a plain `OnFailure=` or healthchecks.io ping covers it, drop it.
- Explain why a trigger did not fire — Check how often you've asked "why didn't it fire"; if the journal answers it in one grep, skip it.
- Stamp every self-started artifact with its origin — Look at the last 10 self-started artifacts; if the branch or commit prefix already makes the origin obvious, skip it.
- Fire a trigger on a fake event for a drill — Pipe a hand-written JSON event into the handler; if that works as a 5-line script, it needs no feature.
- Defer triggers while the user is working in the repo — Check `git status` timing against fires; if collisions are rare, skip it (and idea 5's worktree already avoids it).
- Run missed schedules once on wake, not N times — Test `Persistent=true` on a systemd timer; it already runs once on wake, so nothing to build.
- Show the exact unit text, the enable command and the uninstall line on the install card — Print a systemd unit by hand; if it's 8 lines, a card adds more reading than it saves.
- Declare triggers in a committed repo file — Dupe of 12, 38; if a single `triggers.toml` stub fits in 20 lines, merge them and drop the rest.
- Watch other repos' default branches and review requests — List the repos you'd watch; if it's under 3, `gh` notifications already does this.
- Compile "whenever X, do Y" typed in chat into a trigger draft — Try 10 chat sentences by hand into cron or event specs; if 3 or more are ambiguous, the compiler will guess wrong.
- Turn a drop folder into an inbox — Compare with idea 6; if no one has an inbox habit, it's the same dead idea.
- Offer a trigger after a failure streak in the user's terminal — Count failure streaks in the last month; if under 3, an offer would never show up.
- Write a morning note that reads like a person left it — Read three morning notes aloud; if you can't tell them from a log summary, the "person" voice is cosmetic.
- Show every queued install as one card with one-word answers — Count pending installs at any one time; if almost always 1 or less, a batched card is overkill.
- Preview a trigger on last week before it can install — Replay by hand one trigger on last week's data; if you need fake data for most triggers, preview is useless.
- Give each trigger a name and a one-line receipt when it fires — Dupe of 13; if names already exist in the unit file, drop it.
- Make the stage rail show a trigger as the first step — Ask whether anyone looks at the stage rail; if not, adding to it adds nothing.
- Offer a "quiet hours" dial that slides, not a cron string — Compare a slider to editing one `OnCalendar` line; if you'd edit the line, kill it.
- Tell the user, kindly, when a trigger has never helped — Check if the user would feel judged by "never helped"; one counter in the inventory covers it.
- Wild: Let the night shift leave a postcard from the lane — Show a mockup to one person; if they say "cute" and not "I want it," drop it.
- Wild: Play the night back as a ten-second timelapse in the web UI — Estimate the web UI cost of storing and rendering the night's events; if over a day's work for a toy, drop it.
- Wild: Knock twice to cancel everything — Check for an accidental-cancel scenario that a plain `fm stop` doesn't already handle; none, so drop it.
- Celebrate the first self-started success exactly once — Dupe of 29/13; a one-time banner is 3 lines in the receipt, not a feature.
- Show "what would wake me" as a tiny list on the status line — Check whether the status line has space; if it's already crowded, this fails.
- Declare every trigger in one registry file — Dupe of 12, 21; merge them.
- Catch up missed schedules — Dupe of 2, 19; merge them.
- Render one trigger spec to systemd, launchd and Task Scheduler — Count the platforms actually used; if you're on Linux only, two of three renderers are dead code.
- Watch issues and drafts into the capture inbox — Check issue volume; if under 5 a week, reading them by hand is faster.
- Fire on file and git events with debounce and idempotency keys — Try `inotifywait` plus a `sleep`-based debounce in 10 lines; if that works, skip a framework.
- Watch dependency and advisory feeds for the repo's lockfiles — Run `npm audit` / `osv-scanner` / Dependabot; if they already open PRs, this duplicates them.
- Resume parked lanes when the usage window reopens — Check how often a parked lane actually waits on the usage window; if rarely, a `sleep` loop is enough.
- Dry-run any trigger against its next 7 days — Run `systemd-analyze calendar --iterations=7` on your specs; it already does this.
- Fire a synthetic event to test a trigger end to end — Dupe of 17; merge them.
- Ship trigger recipes that are one yes to install — Write three recipes by hand; if they differ only in a path or schedule, they're docs, not a feature.
- Lease triggers across machines to prevent double fires — Count machines running triggers; if one, leases are pointless.
- Chain triggers into conditional flows — Try expressing your two most complex needs with a shell `&&`; if it works, chains are overkill.
- Wild: compile "when X, do Y" sentences into triggers — Dupe of 23; same ambiguity test applies.
- Wild: mine the user's repeated manual sequences into proposed triggers — Mine your shell history for repeats; if the top sequence occurs under 5 times a month, there's no signal.
- Wild: wake on silence with a "what is rotting" report — Check what a "rotting" report would list today; if it's `git branch --merged` output, it's a one-liner.
- Run one event-envelope dispatcher inside the existing `fm night` tick — Check that `fm night` has a tick loop at all; if it fires on a plain timer with no state, there's no hook for a dispatcher.
- Add a trigger table with a shadow mode before any trigger may start work — Diff shadow-mode output against real output for one trigger; if you'd read neither, shadow mode adds only latency.
- Replay a candidate trigger on the last 30 days of recorded events before asking for its install yes — Check the recorded event retention; if you don't keep 30 days of events, replay has nothing to run on.
- Bundle every install (timer, unit, hook) into one ranked yes card — Dupe of 20 and 27; if one card is 10 lines, ranking is theater.
- Use git hooks and a path watcher instead of a poller for file and commit triggers — Try `git hook` + `systemd.path` on one repo; if inotify limits or remote pushes miss events, it fails, so test with a `git pull`.
- Delegate scheduling to cron or systemd timers by generating the unit and never running a daemon — Generate one unit by hand; if it needs state the unit can't carry (leases, quotas), a daemon returns by the back door.
- Treat issue and CI text as untrusted and let watchers file tasks only, never run them — Feed a poisoned issue body to the watcher; if the filed task text reaches a prompt unescaped, it's an injection route, so restrict output to a fixed schema.
- Cap what a trigger may spend with a per-trigger budget and a storm breaker — Check whether you've ever overspent on one trigger; if the account cap has never been hit, a global cap is enough.
