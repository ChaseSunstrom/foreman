# Brainstorm — lens: the missing verb (invented): every 'command not found', unsupported file type, failed tool call or repeated manual sequence is a request for a tool

- **Log every unknown fm verb or flag as a feature vote** — FEATURE — value 4 — effort S — risk low — category: intake
  Why: assumption: the user's recent asks are mostly new flags (`--bench`, `--migration`, `--jobs N`), so they probably type them first and hit an error. Today that error is lost.
  Done when: `fm task evidence X --nope` exits non-zero and appends a line to a miss log, and `fm triggers` lists it with a count.

- **Catch command-not-found in the user's own shell** — FEATURE — value 4 — effort S — risk low — category: surfaces
  Why: assumption: T-2270 watches only agent sessions, but the user's terminal hits 127 too. A `command_not_found_handle` snippet (bash) that `fm doctor` offers to install, opt-in, would feed those misses to the same trigger.
  Done when: with the snippet installed, typing a missing binary prints the find-or-build hint once and records one miss.

- **Look for the tool on this machine before searching the ecosystem** — FIX — value 4 — effort S — risk low — category: capability-miss
  Why: assumption: many 127s are not missing tools. They are venv, `node_modules/.bin`, `~/.local/bin` or flatpak binaries, or a version without the flag used. Resolving those costs no install and needs no grant.
  Done when: a planted binary in `./node_modules/.bin` makes the miss note say "found at <path>, not on PATH" and queue no grant.

- **Fingerprint inline heredoc scripts as soft misses** — FEATURE — value 4 — effort M — risk low — category: capability-miss
  Why: assumption: T-2270 fires on a missing command or module. A session that writes a 40-line `python - <<EOF` to parse a format throws no error, but it is the same request for a tool. The guard already sees these commands.
  Done when: the same inline-script shape in 2+ sessions files one "build verb" task that cites both.

- **Add `fm can "<capability>"` as a pre-miss query** — FEATURE — value 4 — effort M — risk low — category: discovery
  Why: assumption: `fm plugins find` and `fm lib search` are used after a failure. A single question ("can I diff two parquet files?") that answers have/installable/buildable/no would stop the failure from happening.
  Done when: `fm can "read xlsx"` prints one of four verdicts with the path or the next command, and a session skill calls it before improvising.

- **Search the miss the way a maintainer would** — FEATURE — value 3 — effort S — risk low — category: discovery
  Why: assumption: a model's phrasing ("parse heic") searches badly. Queries built from the error string, file extension and import name would hit better, and zero-result queries become a corpus of real gaps.
  Done when: a miss on `import fitz` runs 3 derived queries, and a zero-hit one lands in a gaps file.

- **Add `fm peek FILE`: any file type to fenced, cached text** — FEATURE — value 4 — effort M — risk med — category: file types
  Why: assumption: converter recipes are listed but no single verb sniffs content (not extension) and dispatches. Converted text is untrusted, so the verb wraps it in a fence marking it as data. The fence is the part nothing else covers.
  Done when: a PDF, a sqlite file and an xlsx each return text through one verb. A PDF containing "ignore previous instructions" comes back inside the data fence.

- **Offer a safe replacement verb for every guard block** — FEATURE — value 3 — effort M — risk med — category: guard
  Why: the guard stops commands the user would never want run, and T-2289 shows `fm lane rm` refusing something the user considered throwaway. A block is a request for a safer verb (trash-with-undo, dry-run first). Today a block is only a no.
  Done when: a blocked `rm -rf` on a scratch path prints the safe verb that does the intended job, and that verb is reversible.

- **Preflight the toolchain at focus** — FEATURE — value 4 — effort M — risk low — category: capability-miss
  Why: the migration proof needs a db client and `--bench` needs a timing tool. Scope paths and criteria already name file types and verbs, so missing tools can be found before the first red run, not during it.
  Done when: focusing a task whose criterion names `--migration` with no sqlite or psql on PATH writes a "missing before start" line into Risks.

- **Keep a verb parity matrix across hosts** — CLEAN — value 3 — effort M — risk low — category: harness
  Why: T-0335, T-0336 and T-0337 are each a verb that works on Claude Code and not on Codex, Gemini or opencode. A table of verb × host, generated by a probe, makes those gaps countable and files each one as a miss.
  Done when: `fm doctor` prints the matrix and each blank cell links to a task.

- **Add `fm wrap BIN`: turn an installed binary's `--help` into a tested verb** — FEATURE — value 3 — effort M — risk med — category: toolsmith
  Why: assumption: much of the missing capability is already on the machine, unknown to the agent. A wrapper with examples and a smoke test written from `--help` makes it usable.
  Done when: `fm wrap jq` writes a wrapper and a test that runs `--version`, and the test fails first.

- **Wild: Teach a verb by doing it** — FEATURE — value 4 — effort L — risk med — category: toolsmith
  Why: wild. `fm learn` records the user's next N commands, with consent and secrets redacted, then turns them into a parameterized script with a failing-first test. It covers manual sequences the user did in their own hands, which event-log mining never sees.
  Done when: a 3-command sequence is recorded, replayed with a different argument, and passes its generated test.

- **Wild: Check invented verbs against the user's own flag habits** — CLEAN — value 2 — effort S — risk low — category: delight
  Why: wild. The user's asks show a grammar (`--bench "<cmd>"`, `--jobs N`, `fm new tool NAME`). A lint that rejects an invented verb whose names or flags break that grammar makes built tools feel native.
  Done when: `fm new tool` warns on a verb named `runTool --Path` and suggests the grammar-conforming spelling.

- **Wild: Draft an upstream bug report when a found tool fails** — FEATURE — value 2 — effort M — risk low — category: ecosystem
  Why: wild. When a found plugin or MCP server fails on a real call, fm writes a local, redacted issue draft (version, repro, error). Nothing is sent; the user decides, so privacy holds.
  Done when: a failing found tool leaves a draft file with a repro command and no paths or tokens from the home directory.
