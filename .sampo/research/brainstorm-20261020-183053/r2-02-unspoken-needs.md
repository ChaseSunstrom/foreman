# Brainstorm — lens: unspoken needs

- **Show an "at a glance" verdict line that survives a blink** — FEATURE — value 5 — effort S — risk low — category: user value
  Why: the user said the TUI "looked like crap with all the text" and was redesigned as pictures; the unspoken need is to know in under a second whether to intervene. Prior ideas are about motion, not a single answer. Assumption: a run can be reduced to one of working / needs you / stuck / done.
  Done when: a golden frame test shows a one-line, color-and-glyph-coded state at the top of every view, and it changes between the four states in a replayed fixture run.

- **Explain why the run is waiting** — FEATURE — value 5 — effort M — risk low — category: observability
  Why: unattended marathon runs are the user's showcase (compaction soak, dollar caps); idle time in a TUI reads as "broken". Assumption: the harness knows whether it waits on the model, a verify command, the guard, or a rate limit.
  Done when: during a fake slow model call and a fake slow verify, the status line names each cause with an elapsed timer.

- **Add a "what changed since I looked away" digest** — FEATURE — value 4 — effort M — risk low — category: user value
  Why: the user runs long unattended work and returns to it; assumption: they scroll to reconstruct events. Distinct from replay: it is a summary on return.
  Done when: after 60 s without input and new events, a dismissible card lists counts of steps closed, guard refusals, red verifies and spend, and disappears on keypress.

- **Show a spend runway against the dollar cap** — FEATURE — value 4 — effort S — risk low — category: observability
  Why: Haiku runs with dollar caps are a recurring ask. A burn gauge exists in ideas, but not a projection ("cap reached in ~14 min at this rate; 3 of 5 steps left").
  Done when: with a fixture cost stream, the gauge shows a projected time-to-cap that updates and turns warning-colored when it is before the projected finish.

- **Make the TUI crash-proof with a plain-text fallback log** — FIX — value 4 — effort M — risk low — category: reliability
  Why: the pack's recent work is all about robustness (worker hardening, CI red on rendering-sensitive timing). An animation bug must never lose a run. Assumption: today a renderer exception can end `fm code`.
  Done when: a test that injects an exception into the renderer shows the run finishing, the terminal restored, and a plain line-per-event log written.

- **Budget the TUI in the CI the way hooks are budgeted** — PERFORMANCE — value 3 — effort S — risk low — category: developer experience
  Why: `bench_hooks.py` and context-tax ratchets exist, and CI broke over CPU-time bounds on GitHub runners; polish adds a new CPU cost the user would not notice until it fails. Distinct from the generic "frame-time budget" in that it uses CPU-seconds per rendered minute, the metric already proven flaky-resistant.
  Done when: a test renders 60 s of fixture events and fails if CPU time exceeds a set bound that is also printed in the report.

- **Print a copy-safe plain view for pasting** — FEATURE — value 3 — effort S — risk low — category: docs
  Why: the user shares results in issues and benchmark pages; a TUI full of glyphs and colors pastes badly. Assumption: they paste into briefs and chats.
  Done when: a key in the TUI writes the current view as plain ASCII text with no escape codes to the clipboard or a file, and the output matches a golden file.

- **Teach through the UI with a first-run one-screen legend** — FEATURE — value 3 — effort S — risk low — category: docs
  Why: the redesign replaced text with pictures (station track, chips, Gantt); newcomers (T-0862/T-0863 deferred) lack a key. Assumption: glyph meanings aren't self-evident.
  Done when: the first launch shows a legend overlay naming each picture element, it is remembered as seen, and `?` brings it back.

- **Let a guard refusal show the way forward inline** — FEATURE — value 4 — effort S — risk low — category: user value
  Why: recent commits add "way forward" hints to guard refusals (T-1288, T-1289); a TUI that flashes refusal but hides the hint wastes them.
  Done when: a refused command in a fixture run shows its verdict and the hint text on the same card, selectable for the full message.

- **Wild: Make the run a bedtime story** — FEATURE — value 2 — effort M — risk low — category: delight
  Why: wild; overnight runs end with a wall of events. A narrated one-paragraph morning summary ("Tonight Foreman closed 4 tasks, refused 2 risky commands...") is built only from receipts, not model prose.
  Done when: `fm code` end card includes a paragraph generated by a template from the event log, with every number matching `fm cost`.

- **Wild: Let the terminal tab title and bell tell you from across the room** — FEATURE — value 3 — effort S — risk low — category: devices
  Why: wild; unattended runs happen while the user works elsewhere. A title like "● fm: step 3/5 · $0.42" and a single bell on needs-you; opt-in only.
  Done when: with the setting on, the title updates on state change and one bell is emitted on a needs-you event in a captured-output test.

- **Wild: Pair the TUI with a phone-readable status page on the LAN** — FEATURE — value 3 — effort L — risk med — category: devices
  Why: wild; the web UI surface already exists per the pack's Surfaces line. Assumption: the user wants to check a marathon from the couch. It must be local-only, token-protected, and off by default.
  Done when: enabling it serves a read-only page showing the verdict line and spend, reachable only with a one-time token, and it stops when the run ends.

- **Wild: Race mode against plain Claude Code** — FEATURE — value 3 — effort L — risk med — category: delight
  Why: wild; the user's top theme is Foreman beating Claude Code on cost and time (T-1231, marathon showcase). A split view of two bench runs with live cost and tests passed makes the argument watchable.
  Done when: replaying two recorded bench runs side by side shows both cost lines and pass counts advancing in time sync.
