# Brainstorm — lens: blind spots

- **Name the class of each "I had to ask" moment before proposing a fix** — FEATURE — value 5 — effort M — risk low — category: blind-spot taxonomy
  Why: The pack lists 8+ missed asks (T-3312 through T-3353). None were caught by any brainstorm. The missing question is: "For this user ask, which *class* of blind spot is it — (a) a fixed set with no ceiling, (b) a surface Sampo touches but doesn't name, (c) a state that persists across rename/migration, (d) a cost that is invisible until the user measures it?" Each missed ask fits exactly one class. The whole project now lacks a *class ledger* that every brainstorm must consult before declaring a cell covered.
  Done when: `samo doctor` prints a one-line "blind-spot class census" listing the count of open items per class, and a new brainstorm pack includes the class of every "asked" line it processes.

- **Ask "what state does this rename/migration *break* on a live machine?" at every name change** — FIX — value 5 — effort S — risk low — category: state persistence
  Why: T-3342 (.foreman/ → .sampo/) and T-2967 (symlink guard path) are both state-persistence breaks that no brainstorm predicted. The question a brainstorm should have asked: "When a path or name changes, which *literal* does the code still compare against?" The class still missing: every `~/.claude/foreman`, `~/.sampo`, `MIRROR_DIR`, `plugin_id`, `marketplace_id` is a *persistence key*. There is no `samo state-keys` verb that lists them and checks each resolves to a real path at session start.
  Done when: `samo state-keys` prints every persistence key, its expected resolved path, and a red mark if it resolves to a dead or symlinked path; the ship gate runs it.

- **Give every fixed set a "what is its ceiling?" line, or refuse to call it a capability** — FEATURE — value 4 — effort M — risk med — category: headroom
  Why: T-3316 (Headroom census) and T-3312 (Kalevala depth) both exist because Sampo never asked "what is the maximum?" The question: "For every number in the code that is a constant, does the user know it can be raised, and by what command?" The class still missing: every constant (funnel batch size, lane max, context budget, GPU slots, moon count) is an *invisible cap*. No brainstorm predicted the user would hit one and have to file a task.
  Done when: `samo caps` lists every named constant, its current value, its ceiling (if any), and the command that raises it; a new brainstorm pack includes a "caps touched" section.

- **Name every external surface Sampo writes into, and what it writes** — SECURITY — value 5 — effort M — risk med — category: egress
  Why: T-3339 (landscape scan) and T-3353 (lessons into prompts) are both "Sampo writes something into a place the user didn't explicitly bless." The question: "For every file, environment variable, git ref, or network call Sampo creates or modifies, is the user aware of it from the docs?" The class still missing: the *egress surface*. No brainstorm predicted the user would notice Sampo writing into `~/.claude/`, `refs/sampo/`, the site's `genesis.json`, or the model's prompt, and have to file a task to understand what went where.
  Done when: `samo egress` prints a table: surface, what Sampo writes, when, and whether the user's standing intent covers it; the ship gate fails if a new egress surface appears without a line in the table.

- **Wire hook latency to a named budget, not just a bench bar** — PERFORMANCE — value 4 — effort S — risk low — category: cost visibility
  Why: T-3352 measured hook_ms but no brainstorm predicted the user would ask "which hook is eating my turn?" The question: "For every hook event, does the user see *which* hook fired, how long it took, and whether it exceeded a named budget?" The class still missing: per-hook cost attribution. The bench measures the total; the user needs the *breakdown* because one slow hook (Ward guard, PostToolUse attribution) can eat 50 ms and make the next tool call feel sluggish.
  Done when: `samo hook-cost` prints a per-hook median and p95, and `samo doctor` flags any hook whose p95 exceeds 20 ms with the command to investigate it.

- **Treat Sampo's own injected prompts as an external surface with an injection scan** — SECURITY — value 4 — effort M — risk med — category: self-injection
  Why: T-3353 (tonight's lessons into prompts) means Sampo is *writing the text that the model reads*. No brainstorm predicted the user would ask "is the text Sampo injects itself safe from the same injection risks as external tool output?" The question: "When Sampo writes text that a model will read (SessionStart, skill descriptions, hook notes, card text), does that text pass through the same fence as untrusted tool output?" The class still missing: *self-injection*. The Ward fences tool output; it does not fence Sampo's own prompt contributions.
  Done when: `samo egress` includes "injected prompts" as a surface, and a nightly scan flags any Sampo-written prompt line that contains a command-shaped string not in the approved verb table.

- **Give the "other machines" surface its own data-flow ledger** — FEATURE — value 4 — effort M — risk med — category: fleet
  Why: T-3321 (fleet claims on git refs) exists because the user has machines beyond this one and Sampo had no concept of "the other box." The question: "When Sampo on machine A writes a git ref, a file, or a model weight that machine B will read, does the user know what crossed, and is it consented?" The class still missing: *cross-machine data flow*. Every `git push`, every model weight transfer, every lesson sync is a data flow between surfaces the user owns. No brainstorm predicted the user would need to audit what went to the other machine.
  Done when: `samo fleet` prints a per-machine ledger: what was sent, what was received, what was consented (via standing intent), and what is pending; a new push that touches a fleet surface without a ledger line fails the ship gate.

- **Make "what did the user have to do by hand this week?" a first-class measurement** — FEATURE — value 5 — effort S — risk low — category: ask debt
  Why: Every missed ask in the pack is a moment where Sampo could have acted but the user had to file a task. The question: "Does Sampo measure the *total* of what the user did by hand that Sampo was capable of, not just what the user filed?" The class still missing: *implicit ask debt*. The user's hand edits, their `git commit` without a Sampo task, their manual `rm` of a worktree, their direct edit of a config file — all are "Sampo should have done this" moments that never enter the ledger.
  Done when: `samo debt` prints a weekly count of hand-done actions (from git reflog, file mtimes outside Sampo's ledger, and the user's own `samo teach` corrections) and ranks the top three by frequency; the morning card shows "you did X by hand this week; here's the task that would stop it."

- **Ask "what does *this box* know that the *other box* doesn't?" at every capability addition** — FEATURE — value 3 — effort S — risk low — category: locality
  Why: T-3321 (fleet) and T-3339 (landscape scan) both assume a single machine. The question: "When a new capability reads or writes local state (model weights, lesson files, card store, embeddings), does the user know whether that state is unique to this box or shared?" The class still missing: *locality contract*. Every capability that touches disk should declare "this state is local to <machine>" or "this state syncs to <surface>."
  Done when: `samo caps` includes a "locality" column for every state-ful capability, and `samo doctor` flags any capability that writes to a shared surface without declaring it.

- **Give the landscape scan a "what does this make obsolete?" column** — FEATURE — value 4 — effort S — risk low — category: obsolescence
  Why: T-3339 (landscape scan) lists new models, APIs, and tools. No brainstorm predicted the user would need to know which of Sampo's own capabilities a new host feature makes redundant. The question: "When the landscape scan finds a new host-native feature, does Sampo check whether one of its own capabilities now duplicates it, and file a retirement brief?" The class still missing: *capability obsolescence by host evolution*.
  Done when: the landscape scan's output includes a "Sampo capability made redundant by" column, and a retirement brief is auto-filed when a host release notes a feature matching a Sampo verb.

- **Give the bench fixture a "what does it *not* cover?" line** — FEATURE — value 4 — effort S — risk low — category: test honesty
  Why: T-3340 (bench fixture) builds 12 candidate tasks. No brainstorm predicted the user would ask "what scenarios does this bench *miss*?" The question: "Does the bench declare its own blind spots — the task kinds, model sizes, or failure modes it does not exercise?" The class still missing: *test coverage honesty*. Every bench and exam should name what it leaves out.
  Done when: `samo bench --report` prints a "not covered" list: task kinds with zero fixtures, model sizes not tested, and failure modes (compaction, crash, usage-limit) not planted in the long-horizon tier.

- **Wild: Run a "Sampo is gone" weekly drill and log what the user had to do by hand** — FEATURE — value 5 — effort M — risk med — category: capability debt
  Why: No brainstorm predicted the user would want to *feel* the cost of Sampo's absence, because the cost is only visible when Sampo is not there. The question: "What does the user do by hand when Sampo is not running, and does Sampo measure that?" The class still missing: *absence measurement*. Every capability's value is defined by what the user stops doing; without measuring the "off" state, Sampo cannot prove it earns its tokens.
  Done when: `samo doctor` includes a "last absence drill" section: date, what the user did by hand (from git reflog and file mtimes during the drill window), and the top three capabilities the drill showed were load-bearing.

- **Wild: Plant a "what I left out" line on every capability's docs, not just every Mission** — FEATURE — value 4 — effort S — risk low — category: coverage honesty
  Why: The "left out" slip exists for Missions (T-3312 era). No brainstorm predicted the user would want the same honesty on *capabilities*. The question: "For every capability Sampo claims to have, what is the one thing it does not do?" The class still missing: *capability-level omissions*. The user files tasks because a capability *almost* does what they need but misses one case.
  Done when: every MASTER.md capability section ends with a "Does not:" line naming the top two omissions, and `samo doctor` flags any capability whose "Does not" list is empty or unchanged for 30 days (suspiciously perfect).

- **Wild: Name the "what is the complete set of things Sampo has *never* been asked to do?" boundary** — RESEARCH — value 4 — effort M — risk med — category: boundary
  Why: T-3312 (Kalevala depth), T-3316 (headroom), and T-3339 (landscape) all probe the edges of what Sampo does. No brainstorm predicted the user would want to know the *complement*: what Sampo has never been asked, and whether it should be. The question: "What is the set of all possible asks minus the set of all filed asks, and is Sampo aware of the gap?" The class still missing: *complement awareness*.
  Done when: `samo boundary` prints a "never-asked" list: task kinds, surfaces, or actions that appear in the host's tool list or the user's git history but have no corresponding Sampo task or capability; the next brainstorm pack includes this list as a "what we haven't tried" section.

- **Wild: Give the user's silence a *boundary*: "what did Sampo say into the silence?"** — FEATURE — value 3 — effort S — risk low — category: egress
  Why: The "silence is not consent" lamp (earlier idea) monitors when the user is quiet. No brainstorm predicted the *reverse*: what did Sampo *emit* during the silence? The question: "When the user is away, does Sampo still write to the site, push to git, send notifications, or modify files? Is the user aware?" The class still missing: *unattended egress*. Every "overnight" capability is a potential egress surface the user may not have blessed.
  Done when: `samo egress` includes an "unattended" column: what was sent or written during each silence window, and whether it was covered by a standing intent; the morning card shows "while you were away, Sampo did X, Y, Z."
